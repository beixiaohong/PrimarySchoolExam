# 2026-09-17 工作日志

## 小说站模块（全新，从 0 到 1）
需求：后台上传 TXT，能自动分章就分，不能则前端下滑请求更多文本；用现有 FastAPI + Vue 实现，
作为单独模块，网站前端入口单独放。

### 架构决策
- **不新建域**：小说属 D2 内容域 → 路由 `app/domains/content/routers/novel.py`，
  后台 `app/routers/admin/novel.py`（复用共享 router）。避免破坏九域 import-linter 契约。
- **前端独立入口**：`web/novel.html` + `web/src/novel/*` 独立 Vue 应用（hash 路由），
  vite 多页 `rollupOptions.input={main,novel}`，后端 `/novel` 返回 `dist/novel.html`。
  与学生端（/）零耦合，共用 `/assets`。
- **章节与流式块共用一张表** `db_novel_chapters`，靠 `novel.chapter_mode` 区分语义
  （chapter=已分章 / stream=流式分块）。前端只有一套「维护 next 指针」的分页代码。

### 关键实现
- `app/domains/content/services/novel_splitter.py`：编码探测（utf-8-sig→utf-8→gbk→gb18030→big5，
  中文占比>5% 判定）+ 章节正则（第X章/回/节/集/篇/部、卷X、Chapter N、序章/楔子/尾声…）。
  分章成立需同时满足：命中≥3、平均单章 100~100000 字、首标题在全文前 30%。**保守优先**：
  宁可判成 stream，也不把正文里偶然的「第一集」误判成目录。
  首个标题前的作者/前言行并入第一章（不丢内容、不产生目录噪音）。
- 跨域调用走 `content.contracts.parse_novel_txt`（admin → *.contracts 白名单），
  直连 services 会违反 import-linter。
- 读者端 `/api/novel/*` **公开**（游客可读，进度/书架才要登录）；
  `GET /{id}/read?from=&limit=` 是下滑加载核心，返回 next 指针。
