## 修复：POST /api/exam/generate 返回 500（DetachedInstanceError）
- 现象：服务器日志 `sqlalchemy.orm.exc.DetachedInstanceError: Instance <ExamRecord> is not bound to a Session; attribute refresh operation cannot proceed`，发生在 `app/routers/exam/generate.py:198` 的 `headers={"X-Exam-Id": str(record.id)}`。
- 根因：`generate_exam` 阶段三用 `with SessionLocal() as db:` 落库，`commit()` 后（默认 `expire_on_commit=True`）`record` 属性过期；`with` 块结束后 record 脱离会话，再访问 `.id` 触发刷新 → 抛错。日志里另有 `数学题年级适配降级：DB 不可用或题型为空` 的 WARNING（数学生成器兜底，非本次 500 主因，但提示 DB 偶发不稳，可后续关注）。
- 修复：在 `db.flush()` 后、`with` 块内取出 `record_id = record.id`，返回时改用 `record_id`。已用 SQLite 复现原错误并验证修复有效。
- 排查过 `records.py`/`wrong.py`/`math.py` 的 `FileResponse`：均在会话内取属性或只返回纯字符串 `filepath`，无同类 detached 问题。
- 提交：`0ddc3a7 fix(exam): 修复 generate 接口 DetachedInstanceError 导致 500`（仅改 1 文件 +4/−1）。本地未 push（按约定 push 前需用户确认）。

## 修复：数学组卷误报 `数学题年级适配降级：DB 不可用或题型为空`
- 现象：日志反复出现该 WARNING（如 `GET /api/study/errors/analysis` 时段附近，实为并发的数学组卷请求触发）。

- 修复：
  1. `_get_available_types`：新增 `db is None` 分支——若已传入 `problem_types`，用 `GENERATORS` 注册表把 code 还原为题型字典返回（仍经 `_filter_by_grade` 年级二次防御），不再误兜底；

- 验证（`.venv`）：`db=None + problem_types` → 返回非空题型字典、正常出题、**不再误报**；`db=None + 无题型` → 仍兜底 + 告警（行为保留）。`py_compile` 通过。
