## 09-29 下午③：对齐 PDF 排版（提交 2135ea5，已推送）

用户再提「效果和 pdf 里面的保持一致」。先去查了 PDF 真实排版（本地
`temp/软考【高项】2026年5月班备考资料/02.../第2章 信息技术发展/`），结论很关键：

**🚨 PDF 文本抽取不保留缩进，层级信息在入库那一刻就永久丢了**
- `read_pdf()` 用的 fitz `get_text("text")` —— 实测**每行行首缩进全为 0**
  （pdfplumber 的 `extract_words()` 才有 x0，本项目没用它）。
- 真实层级靠 x0：如「计算机硬件」x0=94 是 2 级、「程序」x0=185 是 3 级，
  但抽取后两者文本都是 `----程序`，**从 content 反推不出多级层级**。
- 试过用 x0 缩进栈重建（原型 `tools/_dump_gx_levels.py`，不入库）：**不可靠** ——
  同级兄弟有排版噪声（物理层 x0=235 vs 数据链路层 212，差 23pt 却是同级），
  而不同主题的子项缩进量差异极大（5G→3类应用场景 只差 16pt，SDN→3个平面 差 132pt），
  任何固定阈值都会一边误判、一边漏判。此路放弃（除非重新导入时改读 x0）。

**采用的近似（与 PDF 语义一致，够用）**：`----` 分段后
**最后一段＝描述**（渲染成缩进段落、**不带项目符号**），中间各段＝逐级术语
（`•`/`◦`/`▪`），首段＝主题。PDF 原文正是「术语 + 解释」结构：

    网络存储3种技术          → 主题（段落）

## 15:30 本地重解析 PDF 成功还原排版（tools/gx_pdf_tree.py，已推送 13d1c9c）

**真正按 PDF 缩进坐标重建层级**（不再靠 `----` 猜），核心事实与坑：

- **坐标来源**：fitz `get_text("rawdict")` 可拿到**每个字符的 bbox**，不需要 pdfplumber

- **层级判据（实测）**：同级兄弟 x0 差 **< 10pt**（DAS 164.0 / NAS 162.9），

- **四个坑（都导致过明显错误）**：
  1. 按 `----` 切段后**段内已无 dash** → 用 `DASH_RE.search(text)` 判「续行」会全判成续行，
     树直接为空（预览页「新解析空白」的真因）。行级 has_dash 要单独保留。
  2. 连续 **>= 2 个**横线才算分隔符：上标/负号带单个 `-`（`b.s -1`），单个切开会把描述切碎。
  3. **fitz 按 baseline 分行**，`Km²` 的 2、`Gb·s⁻¹` 的 -1 会单独成行，把一整句劈成两段，
     后半段因无 `----` 被当成上一条的描述 → 必须按 y 间距 **MERGE_GAP=12** 把上标吸回正文行
     （正常行距 26pt，不会误合并）。
  4. **同级兄弟有排版噪声**：OSI 七层里「数据链路层」x0=212.2，比其它层的 235.4 偏左 **23pt**。
     只跟栈顶比会让后续兄弟降级成它的子级 → 必须与「父节点已有的兄弟」一并比较（SIB_TOL=12）。
  5. **层级栈必须按页重置**：封面标题「主要知识点清单」居中 x0=207.6，跨页比较时
     会与正经主题的 x0 撞上，把主题弹到根层。

- **卡片粒度 = 每页一张**：`parse_knowledge_lines` 用 `第N章` 标题切卡片，而页眉每页都有
  `第2章 XXX` → 每页 push 一次。所以重解析按页输出即可与线上卡片 1:1 对应，回填不必改条目数。
- **前端配套**：`gxKParseBlocks` 不再 trim 行首空格，**每 2 空格 = 1 级**（`gx-k-lv1..5`），
  缩进优先、无缩进时退回用 `•/◦/▪` 符号类别判层级（旧数据行为不变）。
- 产出样例（`pdf_full_text`，已与 PDF 视觉一致）：
  `网络存储3种技术 / • 直接附加存储DAS / 无需网络、直连… / • 网络附加存储NAS / …`
- **验证**：新增 `tests/test_gx_pdf_tree.py` 9 例（含「排版噪声兄弟」「续行」「跨卡片新行」）；
  全量 pytest **749 例 0 失败**；web 构建 19.59s；regression 7 项全过；lint 2 kept/0 broken。

## 5. 正文回填链路（gx_rebuild_list + gx_apply_content_patch）—— 已完成
- **两步走**（与 gx_pack/import 同一套「本地只读资料、线上只写库」分工）：
  ① 本地 `tools/gx_rebuild_list.py` 读 PDF → `data/gx_content_patch.json`（约 770KB，**data/ 被
  gitignore，要 scp 上传，别走 git**）；② 线上 `tools/gx_apply_content_patch.py`（**默认干跑**，
  `--apply` 才写库）按 `old_fingerprint` **就地更新同一行**，主键不变 → 卡片数量/顺序不变，
  `gx_knowledge_reads` 不断链；重复执行幂等（已回填的行按 new_fp 命中判「已回填」）。
- **对齐算法**（`align()`）：字符多重集 Jaccard（归一化只留 CJK+alnum，`----`/缩进/`•` 全消失
  → 免疫拆行并行；用多重集防长段落靠字表骗分）+ **单调 DP** 把页切连续段分给卡片。
- **三个必踩的坑**：
  1. **段长上限必须动态**：`span_for = ceil(页数/卡数)+2`。固定 4 页时「16 页只 2 卡」的资料
     第一张卡吃不下后半截 → 整份被判分数过低跳过。
  2. **末段必须强制用完所有页**：多重集 Jaccard 会因重复字惩罚「一张卡吃多页」
     （10 页 1 卡时吃 1 页得分反而更高）→ 后面几页被丢弃。只有 dp[n][m] 不可达时才退让。
  3. **没有 `----` 的页不参与对齐**（封面/目录/版尾）：否则 `www.luckeeinc.com`、机构水印
     会灌进正文（封面卡对齐分只有 0.46，正文页都是 1.0）。
- **安全边界**：分数 < 0.45、或新正文归一化长度 < 旧正文一半 → 跳过不写补丁（宁可留旧内容）。
  实测 370 条 → 回填 **333**，跳过 37（多是「重点ITTO」表格页，本就无层级符）；对齐分 ≥0.9 占 94%。
- **验证**：新增 `tests/test_gx_rebuild_list.py` 12 例（单调/不重叠/空页容忍/span 动态/真实
  PDF 端到端）；全量 pytest **761 例 0 失败**；regression 7 项全过；lint 2 kept/0 broken。
- 文档：`docs/高项备考模块说明.md` §2.6 写了完整链路、算法理由与上线命令。
- **预览**：`temp/gx_patch_preview.html` —— 左 PDF 原图、右**前端 gxKBlocksHtml 真实渲染**
  （样式复制自 GaoxiangView.vue），用来确认「回填后用户看到的就是这个样子」。
- **坑记录**：`gx_parse.classify()` **既看文件名也看父目录名** —— 只传文件名
  （如 `x.pdf`）会落到「其他」分支、解析出 0 条卡片（测端到端时踩到）。

## 回填 1062 事故与修复（线上 `--apply` 撞唯一索引）

**现象**：干跑报告「将更新 333 / 冲突 0」，`--apply` 却抛
`1062 Duplicate entry '56590838e1494f99' for key 'gx_knowledge.ux_gx_knowledge_fingerprint'`。

**根因**：补丁里存在「**old 不同、new 相同**」的条目 —— 库里是两行，重解析后正文却完全一致
（分课 PDF 与汇总 PDF 内容重叠）。**逐条查库查不出来**：检查第 N 条时另一条还没写入、指纹
仍是旧值，于是判「未被占用」；真正 flush 才互相撞上。另有 120 组是「old 也相同」（同一张
卡片在补丁里出现两次），第二条查不到 old 行。

**修复（两处）**：
1. `gx_rebuild_list.resolve_fingerprints()` —— 先按 `old_fingerprint` 去重（333→210），
   再对「同 new 不同 old」的组把 `source_file` 纳入指纹；仍撞再纳入 `old_fingerprint`
   （用它而不是递增序号，否则结果依赖遍历顺序、补丁不可重现）。实测 10 条加盐。
2. `gx_apply_content_patch` —— 改成**一次性集合预检** `_plan()`：把所有相关指纹一次捞出，
   在内存里连同「本批内部冲突」一起判；内部冲突按 **id 最小者放行**保证确定性；写库改
   分批（50）+ 逐条 flush + `IntegrityError` 只回滚该批；加载补丁先 `selfcheck()`，
   旧版补丁（含重复新指纹）直接拦下并提示重新生成。

**铁律（通用）**：**批量写库前判唯一索引冲突，必须做「集合预检」而不是「逐条查库」** ——
同一批内的写入互相不可见，逐条判等于没判。干跑报「0 冲突」不等于真的没冲突。
判「本批内部冲突」要按**目标行**去重后再数条目，否则「两条补丁指向同一行」会被误判成冲突。

**验证**：新增 `tests/test_gx_apply_content_patch.py` 13 例（含「真实补丁 + 内存 SQLite
（fingerprint 带 unique）跑 `_plan` 零冲突并真写入」）；`test_gx_rebuild_list.py` 补 5 例
（去重/加盐/顺序无关/最终无重复）。
