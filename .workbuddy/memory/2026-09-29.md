## 高项知识点展现形式优化（提交 7421071，已推送）

用户诉求：「优化高项知识点展现形式」。

**现状问题**：弹层正文是「按行拆段 → 纯 `<p>` 平铺」，PDF/AI 抽取原文里的
「第1章」「一、」「1.」「（1）」与填空的「（）」全糊成一大坨，长清单尤其难读。

**做法**：正文改为结构化块，解析与拼装收敛成纯函数（可 node 直测）：
- `logic/gaoxiang.js::gxKParseBlocks`（结构）/ `gxKBlocksHtml`（HTML）
  · 小标题：`第X章/节`、中文序号「一、」（≤30 字且不含句号）、多级编号（`1.2`/`2.3.1`）
  · 条目：`1.`/`1、`/`（1）`/`•`/`-`；连续条目归组，**按序号形态分组**（数字组 / 括号组分开）
  · 空括号「（）」→ 填空空框；括号内有内容（`（如 GB/T）`/答案区 `（立项）`）保持原文
  · 一律先 HTML 转义再拼装（v-html 双保险）；判定保守（长行宁可当段落）
- computed：`gxKAskParas`/`gxKAnswerParas` → `gxKAskHtml`/`gxKAnswerHtml`（不留两份判定）
- `GaoxiangView.vue`：弹层与答案区改 `v-html`，新增 `.gx-k-h/.gx-k-ul/.gx-k-li/.gx-k-li-no/.gx-k-blank`

**🚨 本轮踩到并固化的坑**：**scoped 样式不作用于 v-html 产出的 DOM**。
构建后规则变成 `.gx-kcontent .gx-k-blank[data-v-x]`，而 v-html 节点没有 `data-v`
→ 一条都不匹配（正文会挤成一坨、空框不显示），**而 SFC 编译、vite build、
测试全部报绿**，只能靠看产物选择器发现。修法：所有后代选择器 `:deep()` 穿透
（编译为 `.gx-kcontent[data-v-x] p`），已写进主记忆「关键坑」。

**验证**：解析断言 14 项全过（标题/多级编号/三种条目分组/空括号→空框/
括号有内容保持文本/段落不误判/HTML 注入被转义）；`verify_vue_sfc` 错误 0；
`web` 构建成功（16.9s）并核对产物含全部新类名与 `:deep` 编译结果；

**验收辅助**：`temp/_gen_gx_preview.mjs`（临时、不入库）用真实解析输出 +
从 SFC 提取的样式（`:deep` 已还原）生成「改版前 vs 改版后」对照页，

## 高项知识点「已读标记」（用户答「需要」，迁移 084）

上一轮记录的最后一项缺口：详情接口没上报 `knowledge_read`。做的时候发现缺口比记录更深一层。

**关键判断：`knowledge_read` 是计数，答不了「哪几条读过」**
`gx_progress.knowledge_read` 是 `Integer` 计数，而列表要给**每条**打已读标记 —— 必须按条查，
计数满足不了。所以新增 `gx_knowledge_reads`（`user_id+knowledge_id` 唯一）作**真相源**，
`knowledge_read` 降级为它的**去重计数缓存**（进度页显示用，沿用「行为时增量、读时零聚合」口径）。

**顺带修掉一个潜在错值**：原设计若在详情每次都 `_bump_progress(knowledge_read=1)`，
用户反复翻看同一条就能把「读过知识点」刷成天文数字。现在**只在首次 +1**（`first_read`）。

**实现**
- `models/gaoxiang.py::GxKnowledgeRead` + `migrations/versions/084_gx_knowledge_reads.py`
  （照 083 范式：幂等建表 → 补列 → 单独建索引；**无历史数据需回填** —— 在此之前
  `knowledge_read` 全仓没有写入路径，所有用户都是 0，不存在「有计数无明细」）。
- `services/gaoxiang.py`：`mark_knowledge_read()` 为**唯一写入口**（明细与计数一起动，
  不留第二处写入）；并发首次靠 `flush()` 立刻撞唯一索引 → 捕获 `IntegrityError` 回滚。
  `read_knowledge_ids()` 批量 IN 查询（列表用，禁 N+1；空入参短路，不让 `in_([])` 进 SQL）。
- `routers/gaoxiang.py`：列表每条带 `read`；详情打开即记已读，返回 `read` + `first_read`。
  GET 带写副作用在此可接受并写了理由（唯一写入是插一行且幂等，前端无预取/无轮询）。
- 前端：弹层 meta 显示「✓ 已读」；列表条目加「已读」角标 + 分组头「已读 x」；
  `gxMarkRead(id)` **就地替换该条**，不重拉列表（保住用户的分节与滚动位置）。

**验证**

- 迁移 084 在测试库跑**两次**均成功，表与 `ux_gx_kread_user_kn` 唯一索引就位。
- `pytest` **740 例 0 失败**（735 基线 +3 新用例 +2 迁移 lint 参数化 → 082→084 新增一个迁移文件，
  `test_migrations_lint.py` 对每个迁移文件参数化 2 例，账目对得上）。
- `verify_vue_sfc` 0 错；`web` 构建 16.9s；产物含 `.gx-read-badge`/`.gx-kitem-flags`
  与「已读」文案；`regression_check` 7 项全过。
- 文档 `docs/高项备考模块说明.md` 同步（表 7→8 张、端点说明、5.1 交互约定、测试用例数 40→43），
