题目来源**两者都要**（AI 生成顶上 + 预留真题导入）。
提交：`3b66a9a`(模型+迁移) / `?`(路由服务) / `?`(测试) / `?`(前端)。

### 架构决策
- 挂 **assessment 域**（与 ai_quiz/grading 同域），前缀 `/api/gx`（11 端点），
  前端 tab `gaoxiang`（桌面侧边栏「学习」组末位；移动 TabBar 6 项已满故不加）。
- **与小学题库完全解耦**：小学侧 subject(语数英)+grade(整数年级) 维度被错题本/统计/收藏
  大量下游假设，高项是成人职业考试（十大知识域 + 单选/多选/案例），强行复用会污染小学口径。
  故独立 6 张表：gx_knowledge / gx_questions / gx_attempts / gx_wrongs / gx_case_grades / gx_progress。
- **不挂 check_quiet_hours**：成人晚间备考是核心场景，宵禁只针对未成年人护眼。
- 真题导入预留：`gx_questions.source=ai|import` + `year`（导入工具为后续项）。

### 关键实现点
- 出题**题库优先**：先取该用户未做过的落库题，不足才 AI 补生成并落库 → 同内容不重复扣费。
- **服务端判分**（答案存库、不下发前端；多选须全对），错题闭环与小学同构（连对 3 次自动掌握）。
- 案例分析：AI 出大题（背景+子问题）→ 作答 → AI 按要点批改评分 0-100 落库。
- AI 调用一律在 DB 会话外；成功后短会话落库 + 按 token 扣钻（失败不阻断）。

### 🚨 两个真实踩坑（都已固化）
1. **`/quiz/generate` 必须用独立短会话回读**：AI 补题写库后若用请求级会话（Depends(get_db)）
   回读，REPEATABLE READ 快照冻结 → 读不到新行，表现为"AI 出题成功但返 0 题"。
   现改为：短会话1 查题库 → 会话外调 AI → 短会话2 回读。
2. **测试里会话 close 后不能再取 ORM 属性**（DetachedInstanceError）：`_seed_question` 改为
   在 commit 后立刻返回 `id`，用例用 id 而不是对象。
3. 测试断言设计坑：用 count=5 验证"题库优先不调 AI"是错的 —— 库存 1 道时 AI 仍会补 4 道
   （属预期）。验证不调 AI 必须让 **count == 库存数**。

### 🚨 纠正上一轮我写错的记忆（重要）
上一轮我记录「全量 pytest 加 `--basetemp=temp/pt` 减少系统 temp 删除拦截」——
**这条是错的，会造成大量假失败**：pytest 收尾 rmtree 该目录时会触发本机安全删除守护的
批量删除拦截 → 抛 `SystemExit` → fixture finalizer 未消费 →
后续用例在 setup 阶段连锁报错（`assert not self._finalizers`），
表现为 build_info/ops_check/preflight/requirements 一片红（25 例）。
**阈值是数量**：小批量跑（74 例）不触发 → 出现"小批量过、全量挂"的迷惑现象，
一度让我误判为"并发改文件竞态"。
**正确做法：用默认临时目录**（系统 temp 在守护的 bypass 名单里），
判通过看 `--junit-xml` 的 failures/errors 计数。
已同步写入 DEPLOY.md §12.1 与本文件下方 MEMORY.md。

## （同日续）备考资料分类入库 + 错题自动分析闭环

用户需求原文：「temp\软考【高项】2026年5月班备考资料 文件夹里面是高项备考资料，需要进行分类并
存储到答题系统中。按照知识点、选择题练习、案例分析练习、论文练习。每个题目做完之后需要自动
分析错题，并将错题进行入库，后续进行练习。」

### 交付
- **解析引擎 `tools/gx_parse.py`**（~1250 行）：分类规则 + 五种解析器（选择题/案例/论文/知识点/其他）
  + 章节归一 + 指纹去重 + 配对（无解析/有解析、答案分离文件）+ 清洗。
- **本地打包 `tools/gx_pack.py`**：602 文件 → 442 解析单元 → 去重后 **4544 条**
  （知识 2851 / 选择 1670 / 案例 17 / 论文 6），产 `data/gx_materials/pack_*.json` + manifest（含覆盖率）。
- **线上导入 `tools/import_gx_materials.py`**：`stats` / `load --dry-run` / `load` / `materials`，
  按内容指纹幂等 upsert（每 300 行提交）。
- **迁移 `082_gx_materials.py`**：新增 `gx_materials` 表 + 资料维度列（`chapter/source_kind/source_file/
  deck/seq/fingerprint/title` 等），`fingerprint` 可空 + 唯一索引。
- **后端**：`/api/gx` 从 11 → **19 端点**（catalog / materials / case-list / case-detail / essay-list /
  essay-detail / essay-grade / wrong-analyze），`QuizGenReq` 加 `domain(可空)/source_kind/chapter/scope/source`。
- **前端**：`logic/gaoxiang.js` 重写 + `views/GaoxiangView.vue` 重写 —— 新增「论文练习」页签、
  错题本题型分栏与错因分析展示、资料/章节筛选、错题重练入口、论文字数统计与四维评分表。

### 关键决策
- **考纲从「十大知识域」扩为 24 章**：真实资料覆盖第 1~24 章，只认十大域会让大半题目无处归置。
- **章节归一三级回退**：章号表达式 → 小节号（`第6.4.1节`）→ 域名反查。缺第二级约 7% 题目域名空。
- **无参考答案的题 `judged=false`**：不判错、不入库、不计分（打印版资料约 5% 没答案，
  误判会把正确答案的题塞进错题本污染错因分析）。
- **错因分析懒生成**：判分接口必须快，AI 每题数秒 → 提交后前端立刻调 `/wrong/analyze`
  （一次自动分析最多 3 题），结果落 `wrong_reason` 缓存复用。
- **`scope=wrong` 不再过滤「做过的题」**，否则错题永远刷不到；按 `wrong_count` 降序（错得多先练）。

### 🚨 本轮修掉的两个真问题
1. **题库取题的窗口 bug**：`quiz_pick` 原来是「取 `n*8` 行再 Python 剔除已做题」，
   用户做满 40 道后窗口内全是旧题 → 明明库里有上千道真题却判「资料不够」回退 AI 出题（白扣费）。
   改为 SQL 层 `~exists()` 相关子查询排除，并加防回归用例
   `test_quiz_pick_excludes_done_at_sql_level`（30 题做掉 25 题、请求 3 题必须还能出 3 题）。
2. **`gx_parse.py` 静默吞掉考纲加载异常**：`_domains_of()` 的 `except: return []` 让 7383 条数据的
   知识域全为空却不报错（表现为「导入成功但知识域全空」）。改为一次性 stderr 告警 +
   `taxonomy_check()` 前置自检，`gx_pack.py` 在打包前调用，不可用时**直接中止**
   （宁可不跑，也不产出全空域的数据包）。
