## 【午后追加】终于找到「零 Web 订阅」的根源：浏览器跟踪防护把 OneSignal 拦了（提交 272edc1）

用户反馈：**设置页「没有弹出授权提示」**，并在 Edge 里看到
「隐私、搜索和服务 → 跟踪防护 → 已阻止的跟踪器 → **OneSignal**」。
这一条直接把上午那个「`players=1` 且只有 `{'Email':1}`」的谜团串起来了。

### 事实链（都可复核）
1. **Edge 的跟踪防护用的是 disconnect.me 的开源 Tracker Protection 列表**（微软官方文档明写）。
   抓 `services.json` 实测：`分类 Advertising → 公司条目 OneSignal → 归属域名 onesignal.com`。
2. **Edge 官方分级处置表**（"Current tracking prevention behavior"）：
   `S` = 仅阻止存储访问；`B` = 阻止存储 **+ 阻止资源加载（网络请求被拦）**。
   | 级别 | Advertising | Analytics | Content | Social |
   |---|---|---|---|---|
   | 基本 | – | – | – | – |
   | **均衡（默认）** | **S** | – | S | S |
   | 严格 | **B** | B | S | B |
3. 我们的实现有 3 处依赖 `cdn.onesignal.com`：`OneSignalSDK.page.js`（590B loader）
   → `OneSignalSDK.page.es6.js`（141KB 真 SDK，**由 loader 自己再去取**）、
   以及 SW 内 `importScripts(.../OneSignalSDK.sw.js)`。站点服务器侧实测三者都 200
   （所以不是 CDN/网络问题），**是被用户浏览器拦掉的**。
4. 链路：脚本被拦 → `window.OneSignal` 永不出现 → **授权提示根本没机会弹**
   → 一个 Web 订阅都建不起来 → 后端一切推送必然 `no_subscription`。

**关键判据（以后别再绕）**：Edge **默认「均衡」只会让广告类「仅阻止存储」**，
脚本仍可加载、仍能订阅；**只有「严格」（或 Firefox 严格 / uBlock / AdGuard / 企业策略）
才会阻止资源加载**，才会出现「连提示都不弹」。所以出现本症状先查用户浏览器的防护级别。

### 🚫 排掉了一条看似合理的弯路：自托管 SDK 资源 **无效**
直觉做法是「把 `page.es6.js` / `sw.js` 下载到自己域名，SW 改 `importScripts('/本地文件')`」。
**分析后否掉**：静态脚本换第一方确实能加载，但 SDK 运行期仍必须请求
`api.onesignal.com`（拉配置 / 注册订阅 / 上报 external_id），它与 `cdn.onesignal.com`
同属 `onesignal.com` 实体 → Strict 下照样被阻止加载 → 订阅仍然建不起来。
另外 v16 的 `OneSignalSDK.page.js` 只是 590 字节 loader，内部**硬编码**了 CDN 上
`page.es6.js?v=160610` 的地址，连 loader 本身也没法自托管。
→ 自托管只能骗过「按 URL 匹配」的静态拦截，骗不过「按域名清单」的跟踪防护，反而多背两个
需要手动跟进版本升级的第三方文件。**结论：这条路不要走。**
