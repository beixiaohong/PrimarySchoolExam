## 🚪 部署前置自检（部署闸门）—— 消除「部署把站点搞挂」（commit 568d6dc，已 push）
### 解决的是什么结构性问题
deploy.sh 原顺序「装依赖 → 构建前端 → **重启服务** → 查进程/健康」，
**检查在重启之后**：坏版本已被 systemd 换上，`Restart=always` 反复崩溃 → 全站 502。
deploy.sh 虽报错退出，但站点已挂、旧进程也没了 ——「部署失败」被放大成「站点下线」。

### 新增 `tools/preflight.py`（纯标准库，venv 坏了也能跑）
两道闸门，都遵循「不通过就不动线上」：
| stage | 位置 | 内容 |
|---|---|---|
| early | chown 之后、**前端构建之前** | 依赖完整性 + 应用可导入 + `.env` 必需键 |
| full | **写 systemd/nginx 配置与重启之前** | 再加外部命令（ffmpeg/soffice/npm）+ 前端产物 |
- 分级只让「真会致挂」的项阻断：BLOCK = 依赖未声明/应用无法导入/.env 缺 DB_*/web-dist 缺失；
  WARN = ffmpeg/ffprobe/soffice/npm/admin-dist/可选 API Key（外部命令缺失只降级功能，不该拦部署）。
- **最有效的一项是真实导入**：用服务所用解释器（root 部署时切到 `--app-user`）跑
  `python -c "import app.main"`；顺带把「git pull 以 root 执行留下的 root 属主文件」问题暴露出来。
- 诊断分两支：`ModuleNotFoundError` 时判断该包是否已在 requirements.txt →
  未声明提示「补进清单」，已声明提示「装了但没进这个 venv」（修法完全不同）。
- 健壮性：`su` 不可用/自身失败时**降级为当前用户跑**并提示，绝不误拦正常部署
  （闸门误报会让人绕过它，比漏报更糟）。
