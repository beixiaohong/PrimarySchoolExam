# 智学学堂（PrimarySchoolExam）优化方案 —— 代码优化 + 功能优化 + 待新增功能

> 审计日期：2026-09-22
> 审计方法：对 `app/`（FastAPI + SQLAlchemy + MySQL）、`web/`、`admin/` 做只读扫描（架构 / 性能 / 安全三个维度），并对两条最高危结论（RBAC、钻石锁）逐行复核。
> 现状口径（实测）：**462 个 HTTP 端点 + 1 个 WS 端点 + `/novel` 独立入口**、迁移至 074、九域契约合规、统一错误信封已落地、持连铁律基本落实、小说站已上线。
> 本文**取代** `docs/优化建议书.md`（该文为 2026-08-12 快照，部分条目已落地或漂移，见末节「旧文档纠偏」）。

## 〇、总体结论（先看这里）

**架构底盘健康，但存在 2 条必须立即收口的红线 + 一批高性价比的工程债务。功能上，教学主线（掌握度 / 知识点）仍是最大缺口，IM/账本的学生端 UI 已建但需打磨，商业化方案已定但落地不完整。**

| 维度 | 评级 | 一句话 |
|---|---|---|
| 架构 / 契约 | 🟢 健康 | 九域独立、跨域只经 `contracts.py`、统一错误信封 `{code,message,request_id}`、持 DB 连接做外部调用铁律基本落实 |
| 安全 | 🔴 2 条红线 | RBAC 灰度未收口（默认放行）、钻石扣费无并发锁（资损竞态） |
| 性能 | 🟡 可优化 | 多处 N+1、高频查询缺索引、分页无上限、weather 同步阻塞 |
| 可维护性 | 🟡 有债 | 上帝文件 im.py(1471) / ledger.py(1093) / paper_crawler(891) / math(655)、重复分页/余额/用户查询、死代码残留 |
| 功能完整度 | 🟡 偏早期 | 掌握度/知识点图谱缺数据底座；支付网关与订单履约方案未全落地；小说站刚起步 |

## 一、代码优化（按严重度 P0 → P2）

### 🔴 P0 · 安全 / 资损红线（建议 1–2 天内收口）

**P0-1 RBAC 灰度未收口 → 越权面**
- 证据：`app/core/permissions.py:98-99` —— `if not RBAC_STRICT: return admin`（config 中 `RBAC_STRICT=false` 为默认）；扫描显示高危写接口（`content/users/commerce/ledger/novel/config` 等）绝大多数仅接 `_require_admin`，**未接 `require_perm`**，全仓仅 7 个文件接入。即任意登录管理员（含 `ops` 只读角色）当前可改内容、封号、动账、核销订单。
- 修复：
  1. 给所有高危写接口补 `Depends(require_perm("xxx:yyy", audit_action=..., high_risk=True))`（权限点目录见 `permissions.py:25-53`）。
  2. 生产环境置 `RBAC_STRICT=true`（先灰度：可在预发环境开 true 跑一遍回归，确保无合法后台操作被误拦）。
  3. 审计日志已就位（放行后写 `AdminOperationLog`），开启即生效。

**P0-2 钻石余额变更无并发锁 → 资损竞态**
- 证据：`app/domains/commerce/services/diamond.py:47-61` 的 `deduct` 为「`query` 余额 → `if balance < amount` → 改 `acc.balance` → `commit`」读改写，**无 `with_for_update`、无 `UPDATE ... WHERE balance >= :amt`**。对比红包 claim 已加锁（`app/domains/frozen/routers/im.py:623`）。并发 AI 扣费（同一用户多请求）在 Repeatable Read 下可双双通过余额判断 → 超发 / 负余额。
- 修复：扣费路径改为 `SELECT ... FOR UPDATE`（在同一短事务内）或条件更新：
  ```python
  rows = db.execute(
      update(DiamondAccount).where(DiamondAccount.user_id == user_id,
                                   DiamondAccount.balance >= amount)
      .values(balance=DiamondAccount.balance - amount)
  ).rowcount
  if rows == 0: return False  # 余额不足，原子拒绝
  ```
  `grant` 同样建议加行锁，避免并发赠送覆盖。

**P0-3 `/api/metrics` 无鉴权 → 敏感运营数据公网暴露**
- 证据：`app/domains/platform/routers/metrics.py:50-51` 与 `app/main.py:153` 挂载处**无任何 `Depends`**，公开返回 `total_users`、`migration_version`、今日订单量、AI token 消耗。
- 修复：加 `Depends(_require_admin)` 或仅内网/带 token 暴露；`_count_today()`（`metrics.py:33-43`）用 `text(table)`/`text(f"{time_col}")` 拼表名，函数签名接受外部字符串属危险模式，改为表名/列名白名单。

### 🟡 P1 · 架构 / 性能（建议 1–2 周内）

**P1-1 上帝文件拆分（降低回归风险）**
| 文件 | 行数 | 拆分建议 |
|---|---|---|
| `app/domains/frozen/routers/im.py` | 1471 | 按 私聊/好友/群/红包/WS 拆子模块到 `frozen/routers/im_*`，主文件 `include_router` 挂载，路径不变 |
| `app/domains/frozen/routers/ledger.py` | 1093 | 账户/分类/交易/周期/统计下沉 `frozen/services/ledger_*`，router 仅留路由 |
| `app/domains/content/services/paper_crawler.py` | 891 | 爬虫抓取与解析分离；`math_generator/calc.py`(668) / `app.py`(655) 按题型拆 |

**P1-2 去重（同一逻辑多处各写）**
- 分页：四处各写 `.offset((page-1)*size).limit(size)` 且返回键名不一致（`commerce.py:143-154` / `audit.py:55-75` / `ledger.py:83-93` / `content.py:135-143`）→ 抽统一 `paginate(q, page, size, schema)`。
- 用户聚合查询：`im.get_user_profile`(1091) / `mastery_store.get_user_mastery_matrix`(131) / `im_crud.get_user_chats`(180) 各自拼 User → 抽 `identity` 用户聚合 service。
- 余额计算：`ledger._adjust_balance` 被调用 5 次，口径分散 → 收敛单一 service 入口。

**P1-3 service → router 反转（越层依赖）**
- 证据：`app/domains/frozen/services/ledger_recurring.py:18` `from app.domains.frozen.routers.ledger import _adjust_balance` —— service 反依赖 router。将 `_adjust_balance` / `_advance_next_run` 下沉到 service 层。

**P1-4 N+1 / 循环内查库（高频路径）**
| 位置 | 问题 | 修法 |
|---|---|---|
| `frozen/routers/im.py:454-459` `get_messages` | 每条消息再查 `User`/`RedPacket` | `joinedload(Message.sender)` + `IN (message_ids)` 批量取红包 |
| `assessment/routers/exam/wrong.py:123→397` | 每条错题再查 `AttemptAnswer` | 按 `question_id IN (...)` 批量预取 |
| `platform/routers/assistant.py:128-134` | 60 天循环每日查 `DailyTask` | 单条 `BETWEEN` 范围查询 + 内存统计 |
| `platform/routers/ai.py:337-343` | 7 天循环查 `DailyTask` | 同上 |

**P1-5 缺失索引（高频过滤字段）**
| 表.字段 | 证据 | 建议索引 |
|---|---|---|
| `AttemptAnswer.attempt_id` / `question_id` | `app/models/exam.py:200-202` | `Index("ix_aa_attempt_q","attempt_id","question_id")` |
| `Message.chat_id` / `created_at` | `app/models/im.py:87` | `Index("ix_msg_chat_time","chat_id","created_at")` |
| `AiQa.q_type` / `ref_id` | `app/models/ai_usage.py:59-60` | `Index("ix_aiqa_type_ref","q_type","ref_id")` |
| `WrongRecord.question_id` | 仅随唯一约束建索引 | 补 `Index("ix_wr_q","question_id")` |

（加索引走 `app/database.py` 的 `_ensure_column` 同款安全机制，跨 dialect 用迁移脚本。）

**P1-6 分页无上限 / 全表返回**
- `im.get_messages` `limit:int=50` 无 `Query(le=...)`（`im.py:436`）→ `Query(50, ge=1, le=200)`。
- `wrong_stats/wrong_practice/wrong_practice_quiz` 均 `.all()` 无 limit（`wrong.py:146,206,263`）→ 加 `LIMIT`/分页。
- `ParentMessage` 固定 `limit(100)` 无分页（`family/routers/parent.py:247`）。

**P1-7 同步阻塞**
- `weather.py:71,79,82` 用同步 `requests.get`×3（最坏 ~30s）且路由为 `def` 同步函数 → 改用 `httpx.AsyncClient` 或线程池；已有进程缓存，命中前置即可。

**P1-8 错误信封绕过**
- `app/main.py:195-198 / 227-229 / 256-258` 直接 `JSONResponse(content={"detail":...})` 绕过统一信封 → 改 `raise HTTPException`（middleware 会包成 `{code,message,request_id}`）。

### 🟢 P2 · 可维护性（有空就做）

- **死代码清理**：`engagement/routers/tasks/custom.py:30-31` 与 `models/custom_task.py` 标注 DEPRECATED 且无引用 → 移 `archive/` 或删；`platform/services/sms.py:23` `# TODO 对接厂商 SDK` 未实现却仍被调用 → 补实现或标注未启用。
- **schemas 覆盖低**：`app/schemas/` 仅 9 文件，多数路由直接 `return {...}` 裸 dict、无 `response_model`（`admin/content.py`、`admin/study_records.py` 等）→ 核心列表/详情补 schema，前端 TS 类型据此生成。
- **星号导入**：`im.py:19-20` `from app.models.im import *` / `from app.schemas.im import *` → 改显式导入，恢复静态检查。
- **后台响应信封不统一**：`users.py:276` / `vip.py:53` / `assets.py:85` 成功响应用 `{"ok":True,"detail":...}` 自创信封，与 `{code,data,message}` 割裂 → 统一。
- **鉴权边界**：`identity/routers/auth.py:243-262` `require_self` 仅校验 query/body 的 `user_id`，不校验 path 参数；IM 路由 29 处用 `require_user`（仅登录）而非 `require_self` → 统一 `require_self` 并解析 path，杜绝新增接口漏绑 user_id 造成越权。

## 二、功能优化（改进已有功能，不另起炉灶）

> 原则：多数能力后端已具备，痛点在**前端未接 / 体验未闭环 / 数据底座缺失**。

1. **IM 即时通讯（后端已完整，前端已建需打磨）**
   - 已读回执 / 撤回：端点已存在（`POST .../read`、`PUT .../messages/{id}`），需补 **WS 广播多端同步**（手机/网页同时在线时状态一致）。
   - 群管理：群主解散/踢人/@全员、消息免打扰、会话置顶。
   - 搜索历史、消息漫游（跨设备拉取历史）、图片/语音消息本地缓存。

2. **账本（WalletView 已商城化，分析能力待前端接入）**
   - 后端已有 CSV 导出（`GET /api/ledger/users/{uid}/export/csv`）、预算/分类统计端点 → **前端接入导出按钮与预算提醒**。
   - 周期交易可视化（D9 已支持自动执行）、收支趋势图表、异常消费告警。

3. **小说站（刚上线，体验缺口明显）**
   - 目录 / 书签 / 进度多端同步（`/progress` 端点已有，需前端调用 + 跨设备）。
   - 站内搜索（书名/作者）、推荐位、阅读主题（字号/背景/翻页）。
   - **TXT 解析鲁棒性**：超大单章（>10 万字）切片边界、解析异常（损坏编码/无换行）兜底 UI 提示；图片/插图类 TXT 暂不支持。
   - 书架分享 / 阅读时长统计。

4. **AI 能力（三链路仅 DeepSeek 可用）**
   - 多供应商故障转移（智谱 GLM / Relay / DeepSeek 当前仅 DeepSeek 通）→ 加健康探测 + 自动降级。
   - 讲解 / 批改 / 周报结果加 `(prompt_hash, model)` 短 TTL 缓存（内存/Redis），直接降 token 成本与延迟（"十万个为什么"已缓存，其余未）。

5. **掌握度与复习（数据底座缺失，功能空转）**
   - `questions` 表缺**知识点字段**、`attempt_answers` 缺**每题用时**（`enterprise/07-技术实施方案` 已列为迁移 053/054 硬前置）→ 不补则掌握度模型、个性化错题本、智能复习队列都无法真正运行。
   - 已有 `study/review-queue`、`study/errors`、`exam/wrong/*` 端点 → 闭环：错题本 → 一键生成同类练习 → 自动入复习队列。

6. **可观测性**：`8c9cade` 已加 OBS-03/04/05，需核对埋点是否覆盖核心转化路径（注册→首考→付费），并接告警（错误率/耗时阈值）。

## 三、需要新增的功能（优先级排序）

> 以下基于「教学主线优先、留存/商业化次之、技术赋能探索」排序，区分 MVP / 增强 / 探索。企业级方案（`docs/enterprise/06-PRD` 等）已细化需求，此处给落地取舍。

### 🥇 MVP（教学核心，先做）
1. **掌握度模型 + 知识点图谱**（依赖迁移 053/054）
   - 知识点掌握度热力图、薄弱点诊断、按知识点智能推题。这是 AI 个性化推荐的底座，缺它其余推荐都是空转。
2. **智能错题本闭环**
   - 错题归因（知识点/题型/粗心）、同类题推荐、间隔重复（Spaced Repetition）自动排期。复用现有 wrong/* 与 review-queue。
3. **支付网关落地 + 订单履约全链路**
   - 现有「人工支付网关」方案（用户下单→线下转账→后台核销→自动发权益）需补齐：支付状态机、超时关单、退款原路、权益自动履约（commerce 已有部分）。未来接微信/支付宝时业务零改动（已设计 `PaymentGateway` 抽象）。

### 🥈 增强（留存与体验）
4. **家长报告（周报/月报推送）**：学习时长、掌握度变化、错题趋势，推送到家长端/微信模板消息。
5. **学习日历 + 打卡可视化**：与现有 learning-goals、focus、checkin 打通，可视化坚持曲线 + 成就。
6. **英语口语 / 听力 AI**：语音评测（已有语音转码底座）、跟读打分、听力模考。
7. **作文 AI 批改**：已有 `ai/grade-essay`、`ai/grade-short-answer` 端点，需补评分维度（内容/结构/语法）可视化与范文对比。
8. **小说站社区**：评论、书架分享、阅读榜单，延长内容消费时长。

### 🥉 探索（技术赋能 / 增长）
9. **题库 UGC / 众包**：与采集系统（`collect_daily.py`、`paper_crawler`）结合，教师/用户贡献题目，经审核入 `questions`。
10. **多端形态**：小程序 / H5 轻量版，降低获客门槛（当前为 Web + Admin 双 Vue 工程）。
11. **运营活动体系**：签到、成就、等级（宠物/徽章已有雏形），提升日活与留存。
12. **个性化首页**：基于掌握度与薄弱点的「今日推荐」聚合页，替代当前分散入口。

## 五、量化预期

- **资损/安全**：阶段 0 后，并发超发钻石风险归零、后台越权面从「任意管理员可写」收敛到「按权限点授权 + 审计」。
- **性能**：补 4 组索引 + 修 N+1 后，消息列表 / 错题列表 / 掌握度查询 P99 预期大幅下降（当前按 `chat_id+is_deleted` 倒序全表扫）；weather 异步后不再占用请求线程。
- **可维护性**：im.py/ledger.py 拆分后单文件 <600 行，Code Review 与回归风险显著下降；统一分页/信封/响应结构后前端对接更稳定。
