## A. 每日签到 + 连续奖励 🟢（推荐首个做）

### A.1 目标与范围
- 学生端每日进入 App 可"签到"一次，得钻石奖励；连续签到 N 天额外阶梯奖励。
- 首页弹窗/顶栏入口，展示"今日已签/连续 N 天/本月日历"。

### A.2 现状复用（零新表）
- **复用 `daily_tasks` 表**：新增 `task_code="checkin"`、`task_type="optional"`、`subject="签到"`（或固定值"其他"），每日首次进入由 `ensure_daily_tasks` 同范式 upsert 一行，`status` 置 `done` 即视为当日已签。
  - 避坑：唯一键不含 `task_type`，签到行与强制任务行 `task_code` 不冲突；"签到"subject 不在 SUBJECTS 三科内，`_get_mandatory_codes` 不处理，需确保生成逻辑不误删（参考 custom task 的 `custom:` 前缀处理）。
- **连续天数**：复用 `badges._streak` 范式，但改为"从 `daily_tasks` 中 `task_code='checkin' AND status='done'` 的日期集合向后推算"，与登录态 `last_login_date` 解耦（更内聚、不被"仅打开 App 未学习"污染）。
- **奖励发放**：直接调 `diamond.grant(db,user_id,amount,reason="daily_checkin")`，并发安全。

### A.3 数据库 / 迁移
- **无需新表**（核心优势）。可选：新增 `checkin_rewards` 配置表（阶梯规则：第3/7/15/30天奖励额），或硬编码在 service 常量（MVP 推荐硬编码，后续可配置化）。
- 若做配置化：迁移 `08x_checkin_config.py` 建表 + 幂等 seed 默认阶梯。

### A.4 后端 API（engagement 域）
- `POST /api/checkin`：幂等签到（同 user+date 已 done 返回"今日已签"+ 当前连续天数）；副作用：`upsert daily_tasks(checkin,done)` + `diamond.grant` + 阶梯判断发额外钻。
  - **铁律合规**：先短会话 `with SessionLocal() as s:` 写签到并 `commit`，**关闭会话后**再 `grant`（grant 内部自带短会话）；外部无 AI 调用，纯 DB，可直接在路由内做，但保持"DB 段短会话"。
- `GET /api/checkin/status`：返回 `signed_today / streak / month_calendar[...] / next_reward_day`。
- 跨域：放 `engagement.contracts`（不直连 services）。

### A.5 前端入口
- `nav.js` 不加独立 tab（避免臃肿），改为：
  - 首页 `HomeView` 顶部队加"签到"按钮（读 `GET /api/checkin/status`，未签则高亮）；
  - 点击 → 复用现有 overlay 弹窗范式（参考 `taskDialog`）展示连续天数 + 月历 + 奖励。
- 顶栏 `💎` 旁可加"🔥连续签到第N天"轻提示。

### A.6 风险
- 签到行被"每日任务重置/清理"逻辑误删 → 生成/清理逻辑需显式豁免 `task_code='checkin'`（同 custom 处理）。
- 幂等：同 date 重复 POST 不得重复发钻 → 用唯一键 `(user_id,date,checkin)` + `grant` 前查 done。

### A.7 工时 / 测试
- **1.5–2 人日**（后端 ~0.5 + 前端 ~1 + 测试 ~0.5）。
- 测试：`tests/test_checkin.py` 钉死幂等（重复 POST 不超发）、连续天数计算（断签归零）、阶梯奖励触发。

## B. 成就系统（升级增强，非从零）🟡

### B.1 目标与范围
- 现有 `badges.py` 是"访问时全量扫描派生授予"，短板：① 实时性差（不访问不授予）；② 多表统计有 N+1 风险；③ 无进度展示（前端只看到"已得/未得"）。
- 升级为：**事件驱动实时授予 + 前端进度条 + 成就分类**。

### B.2 现状复用
- 直接复用 `BADGES` 定义、`BadgeEarned` 表、`_metrics`/`_check` 判定逻辑（不重写）。
- 触发点收敛：在既有"写操作"处埋钩子（首次刷题/满分/掌握错题/连续学习），调用统一 `try_grant_achievements(db,user_id,event)` 服务，仅评估相关徽章（不再全量扫描）。

### B.3 数据库 / 迁移
- **无需新表**。`BadgeEarned` 已有。可选：给 `BadgeEarned` 加 `event` 来源列（迁移 `08x_badge_event.py`，非必须）。

### B.4 后端 API
- 新增 `engagement/services/achievement.py::try_grant(user_id, event)`（纯函数式判定，复用 `_metrics` 子集）。
- 埋点：在 `exam`(首考/满分)、`wrong`(掌握)、`daily_task`(连续天数)、`mood`(心情) 的写提交后调用（注意短会话、不持连接等外部调用）。
- `GET /api/badges` 保留（兜底全量授予），新增 `progress` 字段（当前值/阈值）供前端进度条。

### B.5 前端入口
- `BadgesView.vue` 已存在 → 加"进度条"（读 `items[].progress`）+ 分类 tab（学习/坚持/社交）。
- 解锁时 Toast 通知（复用 `showToast`）。

### B.6 风险
- 埋点处若持 DB 连接调外部 AI → 违反铁律（参考 ledger 卡死教训）。埋点须在 DB 提交、会话关闭后触发；AI 类事件（如"讲解达人"）避免同步判定。
- 事件→徽章映射需避免循环依赖（achievement 服务不得 import 触发方）。

### B.7 工时 / 测试
- **2–3 人日**（服务重构 ~1 + 埋点 ~1 + 前端进度 ~0.5 + 测试 ~0.5）。
- 测试：`tests/test_achievement.py` 钉死事件触发授予、进度计算、不重复授予。

## C. 等级 / 成长体系 🟡

### C.1 目标与范围
- 学生累计学习获得"经验值"→ 升级（如 Lv1~Lv20），等级解锁特权（如每日免费 AI 次数、专属头像框）。
- 经验来源：完成练习数 + 正确率加权 + 学习时长（专注钟）+ 掌握错题。

### C.2 现状复用
- 经验数据源均存在：`ExamAttempt`(练习数/score)、`AttemptAnswer.is_correct`(正确率)、`focus_sessions`(学习时长，专注钟)、`WrongRecord.is_mastered`(掌握)。
- 计算范式可复用 `badges._tree_score`（已聚合学习行为得分）。

### C.3 数据库 / 迁移
- **User 模型加字段**：`level`(int,default=1)、`exp`(int,default=0) — 迁移 `08x_user_level.py`（TEXT 不允许 DEFAULT，用 `_ensure_column` 范式）。
- **等级配置表** `level_config`：lv / min_exp / title / perk — 迁移 `08x_level_config.py` + 幂等 seed 默认 20 级。
- 经验变更走单一 service `add_exp(db,user_id,delta)`（带 `WITH FOR UPDATE` 防并发竞态，复用钻石锁范式）。

### C.4 后端 API（engagement 域）
- `POST /api/level/add-exp`（内部服务，不对外）在关键行为后调用。
- `GET /api/level`：返回 `level / exp / next_level_exp / progress% / perk`。
- 升级事件：达到阈值发钻石/解锁（复用 `diamond.grant` + 通知）。

### C.5 前端入口
- 顶栏头像旁加 `Lv.N` 徽标（复用 `App.vue` 顶栏）；点击 → 新增 `LevelView.vue`（等级进度条 + 特权列表）。
- `nav.js` 加 `level` tab（或并入"我的"）。

### C.6 风险
- User 加列须走 `_ensure_column`（跨 dialect，禁 DEFAULT 于 TEXT/MEDIUMTEXT）。
- 经验计算若每请求实时聚合多表 → 性能（参考 N+1 教训）→ 改为"行为发生时增量加 exp + 落库"，读时直接读 `user.exp`，不实时算。

### C.7 工时 / 测试
- **3–4 人日**（模型/迁移 ~1 + 服务/API ~1 + 前端 ~1 + 测试 ~0.5）。
- 测试：`tests/test_level.py` 钉死 exp 增量/升级阈值/并发 `add_exp` 不超发。

## D. 勋章墙 / 收藏夹 🟢（勋章墙已存在，收藏夹为新）

### D.1 目标与范围
- **勋章墙**：展示已得徽章 + 可展示"荣誉墙"（复用现有 `BadgesView`，轻量增强，几乎零成本）。
- **收藏夹**：学生收藏"好试卷 / 好题目"，个人页查看。

### D.2 现状复用
- 徽章墙：`BadgesView.vue` + `GET /api/badges` 已存在 → D 的"勋章墙"部分**已交付**，仅做展示增强（可选）。
- 试卷：`ExamAttempt` / 试卷表已有；题目：`AttemptAnswer` 已有。

### D.3 数据库 / 迁移
- **收藏夹需新表** `user_favorites`：`id / user_id(idx) / item_type(paper|question) / item_id / created_at`。迁移 `08x_user_favorites.py`。
  - 命名避让：`favorites` 未被占用。

### D.4 后端 API（engagement 域）
- `POST /api/favorites` 收藏 / `DELETE /api/favorites/{id}` 取消 / `GET /api/favorites?type=` 列表（用新 `paginate` helper，page_size clamp[1,200]）。
- 试卷/题目详情由各自域提供（跨域走 contracts，不直连）。

### D.5 前端入口
- `PapersView` / 做题记录详情弹窗加"⭐收藏"按钮 → 调收藏 API。
- 新增 `FavoritesView.vue`（或并入"我的"tab）展示收藏列表。

### D.6 风险
- 收藏 item 删除后 favorire 变孤儿 → 列表查询 LEFT JOIN 或展示时惰性校验；MVP 允许孤儿标记"已失效"。
- 跨域取详情：收藏服务只存 id，详情经 contracts 取，避免循环依赖。

### D.7 工时 / 测试
- **2 人日**（表/API ~1 + 前端 ~0.5 + 测试 ~0.5）。勋章墙增强另计 ~0.5（可选）。
- 测试：`tests/test_favorites.py` 钉死增删查、分页、重复收藏幂等。

## 贰、推荐实施顺序

1. **A 签到**（1.5–2 人日，零新表、复用度最高、用户感知强）→ 立即见效、风险最低。

4. **C 等级体系**（3–4 人日，改动最大）→ 最后做，依赖 A/B 的经验/行为数据。
