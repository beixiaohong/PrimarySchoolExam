# 小说站模块说明

> 独立的在线阅读模块：后台上传 TXT → 自动分章（分不了就按块流式加载）→ 前端 `/novel` 独立入口阅读。
> 技术栈沿用现有 FastAPI + Vue3，**不新建域**（归入 D2 内容域），前端为**独立入口**与学生端隔离。

## 一、入口与访问

| 角色 | 地址 | 说明 |
|---|---|---|
| 读者（C 端） | `https://<host>/novel/` | 独立 HTML 入口 `web/novel.html` + 独立 Vue 应用（`web/src/novel/*`），hash 路由 |
| 后台管理 | 管理后台 → 侧栏「小说站」 | `admin/src/views/Novel.vue`，上传 TXT、上下架、章节维护 |
| 接口 | `/api/novel/*`（读者端）、`/api/admin/novel/*`（后台） | 读者端**游客可读**，仅进度/书架需登录 |

后端由 `app/main.py` 托管 `/novel` 与 `/novel/` 返回 `web/dist/novel.html`（多页构建产物）。
多页配置见 `web/vite.config.js`（`rollupOptions.input = { main, novel }`），两个入口共用 `/assets`。

## 二、数据模型（`app/models/novel.py`，074 迁移建表）

| 表 | 作用 | 关键字段 |
|---|---|---|
| `db_novels` | 书城条目 | `chapter_mode`（chapter/stream）、`chapter_count`、`word_count`、`view_count`、`enabled`、`sort_order` |
| `db_novel_chapters` | 章节 **或** 文本块（两种模式共用） | `novel_id` + `idx` 顺序读取、`title`（stream 模式为空）、`content` MEDIUMTEXT |
| `db_novel_read_progress` | 阅读进度 + 书架 | `(user_id, novel_id)` 唯一、`chapter_idx`、`in_shelf` |

**为什么章节与文本块共用一张表**：两种模式的加载逻辑完全一致（按 `idx` 递增顺序拉下一段），
共用后前端只需一套「维护 next 指针」的分页代码，差异只在是否渲染标题。

## 三、TXT 解析（`app/domains/content/services/novel_splitter.py`）

1. **编码探测**：`utf-8-sig → utf-8 → gbk → gb18030 → big5`，以「中文字符占比 > 5%」判定命中；
   全部不理想时用 GB18030 + `errors='ignore'` 兜底。BOM 直接走 UTF-8。
2. **自动分章**：识别行首 `第X章/回/节/集/篇/部`、`卷X`、`Chapter N`、`序章/楔子/尾声/后记/番外` 等。
   判定成立需**同时**满足：
   - 标题命中 ≥ 3 条；
   - 平均单章字数在 100 ~ 100000 之间（过低=误匹配，过高=标题太少）；
   - 首个标题出现在全文前 30%（否则前面大段无标题正文，目录对不上）。
3. **判定不成立 → 流式分块**：按段落聚合切成 ~2000 字/块，优先段落边界，超长段落按句末标点切，
   仍超 4000 字硬切。标题留空，前端无缝拼接。
4. **保守优先**：宁可判成 stream（读者照样能下滑读完整本），也不要把正文里偶然的「第一集」
   误判成目录，导致几百条垃圾条目。

第一个标题之前的前言/作者行会并入第一章开头，不单独成章（避免目录噪音）。

## 四、阅读加载契约（下滑加载核心）

```
GET /api/novel/{id}/read?from=1&limit=1
→ { items:[{idx,title,content,word_count}], total, next, has_more }
```

- `chapter` 模式：一段 = 一章，前端渲染章节标题，目录可用；
- `stream` 模式：一段 = 一个文本块，`title` 为空，前端不渲染标题、内容无缝拼接；
- 前端维护 `next`：哨兵元素（IntersectionObserver，rootMargin 500px）进入视口即拉下一段，
  并提供「加载下一段」按钮兜底；`next === null` 时显示「全文完」。
- 一次只拉 1 段：首屏快、流量省，天然支持「往下滑再请求更多文本」。

## 五、接口清单

### 读者端 `/api/novel`（公开，不强制登录）
| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/categories` | 分类及数量 |
| GET | `/list` | 书城列表（category / keyword / page / sort=latest\|hot\|title） |
| GET | `/shelf` | 我的书架（需登录） |
| GET | `/{id}` | 详情（人气 +1，登录时回显 `chapter_idx` / `in_shelf`） |
| GET | `/{id}/chapters` | 目录分页（**只给元信息，不含正文**） |
| GET | `/{id}/read` | 按顺序拉正文段（下滑加载） |
| POST | `/{id}/progress` | 保存进度（需登录） |
| POST | `/{id}/shelf` | 加入/移出书架（需登录） |

### 后台 `/api/admin/novel`（管理员鉴权）
| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/upload` | multipart 上传 TXT 导入（20MB 上限，仅 .txt） |
| GET | `/list` | 后台列表 |
| GET | `/{id}/chapters` | 章节列表（`with_content=true` 取全文） |
| PATCH | `/{id}` | 改元信息 |
| POST | `/{id}/toggle` | 上下架 |
| PATCH | `/{id}/chapter/{cid}` | 改章节（同步重算总字数） |
| DELETE | `/{id}/chapter/{cid}` | 删章节 |
| DELETE | `/{id}` | 删书（级联删章节与阅读记录） |

## 六、架构约束

- **不新增域**：小说属 D2 内容域，路由放 `app/domains/content/routers/novel.py`；
  后台路由放 `app/routers/admin/novel.py`（复用共享 `router` 对象）。
- **跨域只经 contracts**：后台导入通过 `app.domains.content.contracts.parse_novel_txt`
  调用解析服务（`.importlinter` 白名单要求 `app.routers.admin.** -> app.domains.*.contracts`）。
- **不持 DB 连接做外部调用**：导入是纯 CPU + DB，无外部阻塞调用，可安全在同一请求内完成。

## 七、部署

```bash
git pull
# 后端：迁移 074 会建表（应用启动时 run_migrations 自动执行）
# 前端：多页构建，必须重建 dist 才会有 novel.html
cd web && npm run build
sudo bash deploy.sh
```

访问 `https://<host>/novel/`；后台「小说站」上传 TXT 即可。
