## 三、问题清单

### P0 学习目标模块「生硬」根因（本次专项）

**P0-1 入口重复**
- 现状：`nav.js` 中 `goals` 同时出现在「学习」组（label=学习目标）和「我的」组（label=目标）→ 桌面侧边栏**两个目标入口**；「我的」组缩进错乱（明显是后手添加）。
- 影响：入口混乱，第一眼就"不融洽"。

**P0-2 与新老两套"目标"并存、互不相通**
- 现状：新「学习目标管理台」（整页 4 Tab，`/api/learning-goals`）与老「学期目标」浮层（Sprint 4，`/api/goals`，3 类固定目标，从今日页浮层打开）**同时存在**，两套数据、两套交互，互不跳转。
- 影响：用户心智分裂——"目标"到底在哪？功能重复且冲突。

**P0-3 视觉体系独立于全站 Token**
- 现状：模块自建紫色体系——`#7c5cff/#9b7bff` 渐变主按钮、`--cool:#f6f7fb` 冷白背景、自绘 `.btn-primary`、卡片 `linear-gradient` 叠色；而全站主色是**蓝 `#4E7CF6`**。
- 影响：一进目标页就像进了另一个 App。且自绘 `.btn-primary` 与全局类名撞名（scoped 隔离但语义重复）。

**P0-4 页内三层导航 + 移动端双底部栏叠加**
- 现状：模块内有左侧 168px 竖排子导航（今日/看板/周报/我的）；移动端该子导航变为 `position:fixed;bottom:0`，与 App 全局底部 TabBar（58px，`z-index:60`）**同屏叠加**，互相遮挡，内容底部预留 76px 也不够。
- 影响：移动端进入目标页出现**双底部栏**，是最直观的"生硬"。

**P0-5 图标体系混排**
- 现状：模块页内是内联 SVG（无 emoji），但全局导航是 emoji。
- 影响：同一产品两种图标语言；导航区 emoji 与页内 SVG 风格割裂。

### P1 结构性（长期）

**P1-1 App.vue 巨型单文件**
- 现状：18 个功能 + 全局逻辑 + 样式全在 `App.vue`（约 3 万行级），首包大、维护难、易冲突。
- 建议：把内联块按模块逐步抽成 `views/*.vue`（与已有 5 个组件同一模式），App.vue 只留壳（侧边栏/topbar/tabbar + 视图分发）。

**P1-2 导航项 21 项偏多、分组不均衡**
- 「学习」组 12 项拥挤；「我的」组重复 goals；移动端大量功能藏在「我的」里。
- 建议：合并同类项（背诵中心/听写/专注钟等可归"练习"子组），收敛一级入口。

**P1-3 图标体系不统一**
- 建议：统一为内联 SVG 图标集（nav.js 配 SVG 组件，参照目标模块的图标方案反哺全站），或至少统一 emoji 规范；避免单模块特立独行。

### P2 功能与入口

**P2-1 移动端无目标入口**：TabBar 6 项无 goals，只能从「我的」进——但「我的」里目前也只有个重复入口。
**P2-2 老「学期目标」浮层缺管理能力**：只能查看/移除，无目标创建/编辑，与新模块能力重叠但不完整。
**P2-3 目标达成后的正向反馈弱**：新模块有撒花，但全站（今日页/统计页）看不到目标进度入口，缺少"目标→日常学习"的联动（如首页展示今日目标量）。

### P3 体验细节

**P3-1 视觉细节**：`--cool` 冷白与全局 `--bg` 接近但不同源；卡片渐变叠色与全局纯白卡片风格不一致。
**P3-2 状态色值**：模块琥珀 `#f5a623` 等与全局 warning 同名不同值，应统一引用 token。
**P3-3 动画**：模块撒花/进度环自成一派，与全局 `fadeIn/popIn` 节奏不同。

## 四、优化方案

### 方案 A：学习目标模块融入（P0 专项，建议优先）

| # | 动作 | 改法 | 工作量 |
|---|---|---|---|
| A1 | **收敛入口** | `nav.js`：删除「我的」组重复 `goals`；仅保留「学习」组单一入口（label=学习目标）。「我的」组恢复 2 项（统计/设置） | S |
| A2 | **统一目标心智** | 老「学期目标」浮层（goalOverlay）改为**跳转**到学习目标管理台（点"学期目标"→ `goTab('goals')` 并在管理台展示该 3 类目标），逐步下线浮层自绘逻辑；短期先在管理台"今日"页顶部放"学期目标快捷卡"引导迁移 | M |
| A3 | **视觉回归全局 Token** | 模块内紫色渐变 → 全局 `--primary`(蓝) 或 `--violet`；`--cool` → `--bg`；自绘 `.btn-primary` 改为引用全局按钮类；卡片/圆角/阴影改用 `--radius/--shadow`；**语义色直接映射** `--success/--warning/--danger`（值已天然接近） | M |
| A4 | **子导航降级** | 删左侧 168px 竖排 `.lg-nav`；四 Tab 改为页内顶部横向 tabs（复用全局 pill 风格）；移动端 `.lg-nav` 的 `position:fixed` 移除 → 页内横向滚动 tabs，**不再叠加全局 TabBar** | S |
| A5 | **图标统一** | 模块页内 SVG 图标保留（质量高），nav.js 的 goals 项 ico 改配同款 SVG；后续全站图标统一时以 SVG 为准 | S |
| A6 | **移动端入口** | TabBar 6 项暂不变；「我的」设置页增加"学习目标"入口卡片（图标与桌面一致） | S |

**A3/A4 完成后预期**：目标页与全站同底色、同主色、同按钮、同圆角；导航层级 = 侧边栏 → 页内横向 tab（与全站"单页内容"范式一致）；移动端无双栏叠加。产品逻辑（休息日/推算/置顶/周报）全部保留，只换皮不换骨。

## 六、风险与约定

- 所有改动遵循项目约定：每完成一个可独立验证模块即 commit；前端保持可构建（`cd web && npm run build` 通过为准，沙箱 vite 受限时在服务器验证）；后端改动上线前跑全套 pytest。
- A2 涉及老目标浮层逻辑变更，注意保留 `/api/goals` 兼容（或提供迁移脚本），避免老用户数据丢失。
- A3 换色时用 `var(--primary)` 等 token 引用而非硬编码，保证后续全站换主题只需改 style.css。
- 图标统一（B3）是全站级改动，建议单独立项分批做，避免与其他重构互相污染。
