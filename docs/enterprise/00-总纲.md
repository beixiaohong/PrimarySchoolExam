# 智学学堂 · 企业级方案总纲

> 编制日期：2026-09-02 · 适用范围：智学学堂（PrimarySchoolExam）从「个人开发项目」升级为「企业运营级产品」
> **本套文档只做方案，不含代码实现**。所有现状数据均由代码实测得出（口径同 `PROJECT_STRUCTURE.md`），竞品与合规数据取自 2026 年公开资料。

---

## 一、一句话结论

智学学堂的**功能广度已经接近入门级商业产品**（377 个端点、30 个功能模块），但**商业闭环、效果闭环、合规底座、可观测性四项为零**，且 **19% 的代码量（IM + 个人账本共 71 个端点）与 K12 学习主线无关**。

升级为企业运营级，核心不是「继续加功能」，而是：

1. **做减法**：冻结与主业无关的社交/账本模块，资源集中到学习主线；
2. **补底座**：交易体系、掌握度模型、合规体系、可观测性——这四件事决定能不能规模化；
3. **建组织**：从「一人全栈 + AI 辅助」升级为「按域负责的小队制」，并用流程把质量固化下来。

## 二、现状体检（代码实测）

### 2.1 已有资产（这是优势，不要推翻重来）

| 维度 | 实测值 | 评价 |
|---|---:|---|
| HTTP 端点 | 377（45 个前缀） | 功能覆盖广度足够，超过多数同阶段创业产品 |
| ORM 模型 | 85 类 / 40 文件 | 数据建模完整 |
| 迁移脚本 | 56（026+ 幂等） | 自建迁移系统可用，但需规范化评审 |
| 自动化测试 | 124 用例 / 20 文件 | 主线覆盖尚可（任务/数学/出卷/判分） |
| 出题引擎 | 数学 13 子包 + 英/语/初中 | **核心壁垒雏形**，自研可控 |
| AI 接入 | 三链路 fallback + 钻石计费 | 架构正确，需补成本治理与评测 |
| 内容采集 | 第一试卷网日采 200 份 | 内容供给管线已通 |
| 家长/激励体系 | 任务双轨 + 家长自定义 + 补签卡 | 契合家庭教育场景，差异化点 |

### 2.2 致命缺口（端点级实测，不是推测）

对全部 377 个端点做关键词命中统计：

| 能力 | 命中端点数 | 判读 |
|---|---:|---|
| `pay` / `order` / `subscr`（支付/订单/订阅） | **0** | **没有交易体系**。钻石靠 `/api/diamond/recharge/config` 二维码人工充值；VIP 仅 `/api/admin/vip` 后台手动开关 |
| `invite` / `share` / `channel`（邀请/分享/渠道） | **0** | 无增长机制、无渠道归因 |
| `push` / `notify`（消息触达） | **0** | 除 IM 与公告外，无召回能力 |
| `metric` / `monitor`（指标/监控） | **0** | 无可观测性；仅有 1 个返回硬编码 `healthy` 的探针，**不检查数据库** |
| `teacher` / `school` / `org`（B 端角色） | **0** | 仅 C 端学生 + 家长，无老师/班级/机构 |
| `audit` | **0** | 有基础操作审计表 `admin_operation_logs`（VIP 等已落审计），但无全局请求级审计 / request-id / 合规审计能力 |
| `report` | 2 | 仅 AI 周报与账本报表，无经营分析报表 |

**基础设施层同样薄弱**（`app/main.py` 实测）：无 CORSMiddleware（同源托管）、**无任何中间件**、**无全局异常处理器**、**无 request-id 追踪链路**。这意味着线上出问题时只能靠翻日志文本定位。

### 2.3 代码结构风险

| 文件 | 行数 | 风险 |
|---|---:|---|
| `web/src/logic/appOptions.js` | 3,643 | 学生端逻辑集中在单一 mixin，任何人改动都可能波及全局 |
| `app/routers/im.py` | 1,251 | 迁移而来的外部模块，与主业无关却占最大路由文件 |
| `app/routers/ledger.py` | 1,086 | 同上 |
| `app/services/paper_crawler.py` | 891 | 采集流程与解析耦合 |
| `app/services/math_generator/calc.py` | 658 | 题型实现体量大 |

**测试覆盖盲区**：`/api/im`（29 端点）与 `/api/ledger`（42 端点）合计 71 个端点**零自动化覆盖**；而这两个域恰恰是与主业无关的。

## 三、竞品认知（2026 现状）

### 3.1 作业帮

- 题库 19 亿+，视频讲解覆盖率 93%，拍照搜题响应 0.8s，日更新 20 万道题目。
- 自研银河大模型，学习机端「AI 超级老师」实现**学情诊断 → 动态学习计划**完整闭环；2026 年定位从「工具型 App」转向「教育智能体」。
- 2026-01 作为核心起草单位参与《生成式人工智能错题分析系统技术规范》（T/CIET 2297-2026）团标——**用标准建立行业话语权**。
- 双端策略：学生端重自主练习与输入，家长端重检查、管控与效果评估。
- 软硬一体：学习笔、错题打印机、学习机，构建数据闭环与用户粘性。
- 商业化：VIP 会员覆盖视频讲解、专项练习、同步课。

### 3.2 猿辅导 / 小猿AI

- 2025-04 小猿口算升级为「小猿AI」，整合小猿搜题 30 亿题库，形成九大功能：作业检查、拍照搜题、答疑讲解、专项练习、作文批改、错题本、同步学练、备考工具、**班级功能**。
- **班级功能是 B 端杠杆**：日批改 5 亿题，服务 450 万小学老师，老师用高频错题统计反哺 C 端。
- 定价体系（公开渠道）：VIP 1 月 25 / 3 月 88 / 12 月 398 元；SVIP 年卡 298 元；促销年卡 178 元。**订阅制 + 分层权益（VIP/SVIP）是标准打法**。
- 模型策略：DeepSeek 推理模型 + 自研猿力大模型双基座——**推理能力定位错因，自研模型保障教育专业性与安全性**。
- 学习机 T6「超级学练智能体」以**掌握度模型**牵引「诊-学-练-测」全链路闭环，三层架构：数据层 → 应用层 → 效果层。
- 内容：500 万+ 课时同步视频，人教官方授权，100% 匹配校内教材。
- 治理细节：口算 PK 上线后 2 天内即补「成年人验证机制」，防止成年用户破坏未成年人竞技体验——**合规与体验治理的响应速度是竞争力**。

### 3.3 行业趋势（2026）

1. **政策驱动标准化**：教育 AI 从鼓励探索转向具体落地要求，标准化功能模块可进入政采通道。
2. **AI 助教成标配**：从辅助批改切入，逐步扩展到备课建议、课堂提问生成。
3. **个性化实时动态调节**：基于答题速度、错误类型、专注时长分钟级调难度。松鼠 Ai 1662 人实验显示 AI 教学组成绩显著优于真人组，低分组平均分 47.9 → 72.5。
4. **教育智能体情感化**：情绪识别与动机激发（如学而思 AI Buddy 内置情绪计算引擎），但需给学生控制权、明示是 AI。
5. **效果量化成为核心卖点**：竞争焦点从硬件配置/功能数量转向**学习流程重构与效果真实提升**。

### 三条战略判断

**判断一：不要继续横向加功能，先补「效果闭环」。**
竞品的代际优势不在题量，而在**掌握度模型**——它把「做了多少题」变成「掌握了多少」。智学学堂目前只有 `study_errors`、`wrong_records` 等离散数据，没有「学生 × 知识点」的掌握度矩阵，因此所有推荐只能是粗粒度规则。**这是产品代际的分水岭，P0 中的 P0。**

**判断二：IM 与个人账本必须冻结并隔离。**
71 个端点（占 19%）、2,337 行最大的两个路由文件、零测试覆盖——这三件事叠加，意味着它们持续消耗维护成本却不产生主业价值。好在它们的表已用 `db_im_*` / `db_ledger_*` 前缀隔离，**物理拆分成本极低**。建议：冻结新需求 → 剥离为独立模块 → 视战略决定是否独立部署或下线。

**判断三：合规不是上线前的检查项，是商业化的前置条件。**
无支付体系时用户量小、风险敞口小；一旦做订阅制规模化，未成年人个人信息处理、内容安全、等保、备案每一项都是监管实打实的处罚点。**先建合规底座，再开商业化闸门。**

## 七、给决策者的三条建议

1. **先花 3 个月补底座，不要急着加功能。** 在掌握度模型、交易体系、合规、可观测性四件事完成前，任何新功能都会建在沙子上，且会持续放大维护成本。

2. **立刻冻结 IM 与个人账本的新需求。** 这两块占 19% 端点、零测试覆盖，是纯成本中心。冻结后把释放的精力投入学习主线，收益远大于继续投入。

3. **组织建设优先于功能建设。** 从「一人全栈 + AI 辅助」到「小队制按域负责」，真正的瓶颈不是能不能写出来，而是**多人协作时质量不塌方**。流程规范与岗位分工看似是「管理成本」，实则是规模化的前提。
