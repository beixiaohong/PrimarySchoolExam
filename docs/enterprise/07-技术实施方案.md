## 2. 总体架构与模块边界

### 2.1 分层约定

```
app/
├── domains/                  ← 业务域（D1–D9），唯一承载业务逻辑的地方
│   └── <domain>/
│       ├── contracts.py      ← 对外契约（其它域只能 import 这个）
│       ├── routers/          ← HTTP 层：参数校验、鉴权、调用 service
│       ├── services/         ← 业务逻辑：可测试、不依赖 FastAPI
│       └── README.md         ← 域说明：数据归属 + 迁入清单
├── models/                   ← 数据模型（按域分文件，统一在 __init__ 注册）
├── schemas/                  ← Pydantic 请求/响应模型
├── core/                     ← 【本期新增】跨切面基础设施
│   ├── middleware.py         ← request-id / 访问日志 / 异常处理
│   ├── logging.py            ← 结构化日志
│   ├── metrics.py            ← 指标采集
│   ├── permissions.py        ← RBAC 依赖
│   └── config.py             ← 配置读取（含支付网关选择）
└── migrations/versions/      ← 迁移脚本
```

**依赖方向（单向，禁止逆向）**

```
routers → services → models
   ↓          ↓
contracts ← 其它域只能 import 本域 contracts.py
```

- 跨域调用**只能**通过目标域的 `contracts.py`。
- 冻结域 D9 允许被 `main.py` 挂载，但 D1–D8 不得 import 其任何内部模块。
- 静态扫描规则（纳入 CI）：D1–D8 代码中不得出现 `from app.domains.frozen.`（除 `contracts`）以及跨域 `from app.domains.<other>.routers/services`。

### 3.2 核心表设计

#### 3.2.1 题目-知识点映射（迁移 053）

```sql
-- knowledge_points 补字段（用 _ensure_column，避免 TEXT DEFAULT 报错）
ALTER TABLE knowledge_points ADD COLUMN parent_id      INT DEFAULT 0;      -- 父知识点（层级）
ALTER TABLE knowledge_points ADD COLUMN code           VARCHAR(64) DEFAULT '';  -- 知识点编码
ALTER TABLE knowledge_points ADD COLUMN sort_order     INT DEFAULT 0;
ALTER TABLE knowledge_points ADD COLUMN status         VARCHAR(16) DEFAULT 'active';
ALTER TABLE knowledge_points ADD COLUMN textbook_ver   VARCHAR(32) DEFAULT '';  -- 教材版本
ALTER TABLE knowledge_points ADD COLUMN updated_at     DATETIME NULL;
CREATE INDEX idx_kp_parent ON knowledge_points(parent_id);
CREATE INDEX idx_kp_code   ON knowledge_points(code);

-- 题目-知识点映射（一题多知识点）
CREATE TABLE question_kp_map (
  id             INT AUTO_INCREMENT PRIMARY KEY,
  source_table   VARCHAR(32)  NOT NULL DEFAULT 'questions',  -- questions / paper_questions / middle_questions
  question_id    INT          NOT NULL,
  kp_id          INT          NOT NULL,
  is_primary     TINYINT      NOT NULL DEFAULT 1,   -- 1=主知识点(权重1.0) 0=副知识点(权重0.5)
  weight         DECIMAL(4,2) NOT NULL DEFAULT 1.00,
  source         VARCHAR(16)  NOT NULL DEFAULT 'manual',  -- manual / ai_pred / batch_import
  confidence     DECIMAL(4,3) NOT NULL DEFAULT 1.000,     -- AI 预标注置信度
  annotated_by   VARCHAR(64)  NOT NULL DEFAULT '',
  reviewed_by    VARCHAR(64)  NOT NULL DEFAULT '',
  status         VARCHAR(16)  NOT NULL DEFAULT 'active',   -- active / deprecated
  created_at     DATETIME     NOT NULL,
  updated_at     DATETIME     NULL,
  UNIQUE KEY uq_qkm (source_table, question_id, kp_id),
  KEY idx_qkm_kp (kp_id),
  KEY idx_qkm_src (source_table, question_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

**设计说明**
- 用独立映射表而非在 `questions` 上加列：① 一题多知识点；② `paper_questions`/`middle_questions` 同样需要标注，统一模型；③ 加列要动 3 张表，映射表只需一张。
- `weight` 与 `is_primary` 冗余但有用：`is_primary` 供查询过滤，`weight` 供算法计算，避免算法里写魔法值。

#### 3.2.2 答题用时（迁移 054）

```sql
-- 实测确认：attempt_answers 现有列仅 id / attempt_id / question_id / user_answer / is_correct
-- 无 created_at、无 seq、无难度，以下 4 列全部为新增
ALTER TABLE attempt_answers ADD COLUMN started_at  DATETIME NULL;
ALTER TABLE attempt_answers ADD COLUMN duration_ms INT DEFAULT 0;      -- 单题用时（毫秒）
ALTER TABLE attempt_answers ADD COLUMN seq         INT DEFAULT 0;       -- 题序，便于还原答题过程
ALTER TABLE attempt_answers ADD COLUMN difficulty  TINYINT DEFAULT 3;   -- 冗余题目难度，避免回查
ALTER TABLE attempt_answers ADD COLUMN created_at  DATETIME NULL;       -- 作答时间
CREATE INDEX idx_aa_question ON attempt_answers(question_id);
CREATE INDEX idx_aa_created  ON attempt_answers(created_at);
CREATE INDEX idx_aa_attempt  ON attempt_answers(attempt_id);
```

> ✅ **已实测确认**（2026-09-02 核对 `app/models/exam.py:193-211`）：`attempt_answers` 现有列仅 `id / attempt_id / question_id / user_answer / is_correct`，上述 5 列全部为新增。
>
> **作答时间兜底**：`created_at` 为空时，退化用 `exam_attempts.created_at`（整卷提交时间）减去该题之后的用时估算，精度不足则标记为「时间未知」。

**存量数据处理**
- 存量 `duration_ms` 统一置 0，掌握度算法中 `duration_ms = 0` 视为「无用时数据」，用时因子取中性值 1.0（不加不减），不污染计算。
- 掌握度首次计算时，仅对**有标注且有用时数据**的答题记录做完整计算；其余走降级公式。

## 5. 关键技术方案

### 5.1 掌握度计算

#### 5.1.1 计算架构

```
答题完成
  ↓
(1) 同步：写 attempt_answers（含 duration_ms）→ 提交事务 → 释放 DB 连接
  ↓
(2) 异步：投递 mastery 计算任务（进程内线程池 / 或简单 DB 队列表，本期不引入 MQ）
  ↓
(3) 计算服务：
     拉取该用户最近 N 次作答（有 kp 标注的）
     → 按 kp 分组 → 逐 kp 计算 → UPSERT mastery_records
  ↓
(4) 每日 01:00：全量重算活跃用户（活跃 = 近 7 天有作答）
  ↓
(5) 每日 01:30：对活跃用户生成 mastery_snapshots
```

> 🔴 **必须遵守项目铁律**：**严禁持有 DB 会话时发起外部阻塞调用**。掌握度计算为纯 DB 计算，无外部调用；若需 AI 预标注则必须「短会话读 → 关闭 → 调 AI → 短会话写」。

#### 5.1.2 算法实现要点

```python
# app/domains/engine/services/mastery.py
ALGO_VERSION = "v1"

def compute_mastery(records: list[AnswerRecord], params: MasteryParams) -> MasteryResult:
    """纯函数：给定作答记录与参数，输出掌握度。无 IO，便于单测。"""
    # 1. 只看有 kp 标注的记录（BR-M0-1-04）
    # 2. 时间衰减加权：w_i = exp(-(now - answered_at).days / params.lambda_days)
    # 3. 加权正确率 C_adj，用时因子 T（duration_ms=0 时取 1.0 中性值）
    # 4. 难度权重 D_weight，连续正确 streak_bonus
    # 5. 与先验 prior 按总权重混合，clamp 到 [0,100]
    # 6. confidence = min(1.0, effective_sample_size / params.confidence_n)
```

- 参数全部走配置（`system_config` 或环境变量），支持 A/B 实验。
- 算法为**纯函数**，输入输出确定，单测覆盖边界（0 条记录 / 全对 / 全错 / 全是 0 用时 / 极端难度）。

#### 5.1.3 性能策略

| 策略 | 说明 |
|---|---|
| 增量计算 | 只算「有新增作答的 (user, kp)」组合，不全量重算 |
| 批量 UPSERT | 用 MySQL `INSERT ... ON DUPLICATE KEY UPDATE` 批量写 |
| 分页拉取 | 拉取作答记录按 user_id 分页，单批 ≤ 1000 条 |
| 异步化 | 答题接口不等待计算结果 |
| 冷启动 | 首次全量计算走离线脚本（`tools/recompute_mastery.py`），分批跑，避免长事务 |

### 5.2 人工支付网关与订单状态机

#### 5.2.1 支付网关抽象

```python

class PaymentGateway(Protocol):
```

## 7. 迁移与灰度方案

### 7.1 迁移执行原则

| 原则 | 说明 |
|---|---|
| 顺序执行 | `runner.py` 按文件名排序，依次执行未应用版本 |
| 幂等 | 建表 `checkfirst=True`，加列 `_ensure_column`（异常兜底），数据回填用 `UPDATE ... WHERE NOT EXISTS` |
| 可逆 | 每个迁移脚本在 docstring 中写明「回滚方案」（DROP 表 / DROP COLUMN / 数据恢复方式） |
| 双跑验证 | 预发环境先跑一遍，再跑第二遍确认无副作用 |
| 大表加列 | `questions` / `attempt_answers` 为大表，加列前评估锁表时间；MySQL 8 支持 `ALGORITHM=INSTANT` 的加列优先用之 |
| 备份 | 每次迁移前全量备份；生产环境迁移窗口选在凌晨低峰 |

### 7.2 灰度策略

| 需求 | 灰度方式 | 开关 | 回滚 |
|---|---|---|---|
| 掌握度计算 | 内部账号 → 5% → 20% → 100% | `MASTERY_ENABLED` + 用户 ID 哈希白名单 | 关开关；清空 `mastery_records` 重算 |
| 学习路径 | 与掌握度同批 | `PATH_ALGO=personalized/rule` | 降级为规则推荐（BR-M1-2-05） |
| 交易体系 | 内部测试 → 存量 VIP → 全量 | 商品 `status` 一键下架 | 下架全部 SKU；已产生订单保留可查 |

| RBAC | 一次性切换（先给所有存量管理员赋 superadmin） | — | 保留「跳过权限校验」应急开关（`RBAC_STRICT=false`，仅应急） |
