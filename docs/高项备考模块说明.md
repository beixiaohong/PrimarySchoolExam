# 高项备考模块说明（软考高级 · 信息系统项目管理师）

> 面向**非学生成人用户**的备考模块，入口 `tab='gaoxiang'`（导航「高项备考」）。
> 与小学侧完全独立：不挂 `check_quiet_hours`（成人晚间备考是核心场景），
> 科目/年级/教材版本维度均不共享。
>
> 最后更新：2026-09-29（填空辅助记忆清单 → 完整知识点； StateSwitch 全站统一开关）（迁移 084 已读明细表、已读标记、前端统一开关控件 StateSwitch）

---

## 一、它解决什么问题

备考资料散落在 `temp/软考【高项】2026年5月班备考资料` 里的 602 个文件（PDF / Word / 图片），
人工翻找无法形成练习闭环。本模块把资料**按四类落进数据库**，并在做题后**自动分析错题、入库、供后续重练**：

| 类别 | 落表 | 前端入口 | 判分方式 |
|---|---|---|---|
| 知识点 | `gx_knowledge` | 知识点页签 | 不计分（阅读） |
| 选择题练习 | `gx_questions`（`qtype=single/multi`） | 刷题页签 | 服务端判分（字母归一比对） |
| 案例分析练习 | `gx_questions`（`qtype=case`） | 案例页签 | AI 按要点批改 |
| 论文练习 | `gx_questions`（`qtype=essay`） | 论文页签 | AI 四维评分 |
| 其他（未命中规则的资料） | `gx_materials` 归档 | — | 仅审计，可回溯为什么不入库 |

## 二、资料 → 题库的数据流（本地打包 → 线上写库）

```
temp/软考【高项】…/*.pdf
        │  ① tools/gx_parse.py   解析引擎（分类 / 章节归一 / 五种解析器 / 指纹去重）
        ▼
   data/gx_materials/pack_*.json + manifest.json      （本地产出，不连数据库）
        │  ② scp 上传（只传数据包）
        ▼
   线上服务器 ③ tools/import_gx_materials.py load      （幂等写 MySQL）
```

两段式的原因：解析依赖 PyMuPDF（必要时 LibreOffice 处理 OLE 二进制 .doc），本地方便；
而写库必须落在**线上真库**——本地 `.env` 指向的是线上库克隆（`192.168.2.158`），
铁律：绝不对克隆库跑写库脚本。

命令与体量见 [DEPLOY.md §5.5](../DEPLOY.md#55-高项备考资料导入可选一次性)。

### 2.1 分类规则（`tools/gx_parse.py: classify()`）

按**顶层目录**判类别，再看子目录/文件名判子类；命中不了进 `其他` 并记 `reason`。
顶层目录名本身有陷阱（如「知识点」目录里混着每日一练截图），因此子类判定优先于目录名。

### 2.2 章节归一（`app/domains/assessment/services/gaoxiang.py: normalize_chapter()`）

三级回退，缺一级就大面积空域：

1. 章号表达式：`第12章`、`第6、7章`、`第8~10章` → 第 8/9/10 章；
2. 小节号：`第6.4.1节` → 第 6 章（每日一练文件名大量使用，不认它约 7% 题目域名空）；
3. 域名反查：`风险管理` → 第 15 章（别名表 `DOMAIN_ALIASES`，长键优先）。

考纲已从早期「十大知识域」扩展为**第 1~24 章**（信息化发展 / 信息技术发展 / 绩效域 /
法律法规与标准规范…）——真实资料覆盖全书，只认十大域会让大半题目无处归置。
第 8~17 章名称保持与旧版一致，便于既有数据对齐。

### 2.3 去重与幂等（同一套指纹）

`fingerprint()` = `sha1(归一化文本)[:16]`，落在 `gx_questions.fingerprint` /
`gx_knowledge.fingerprint` 的**唯一索引**上（列可空：MySQL 唯一索引允许一个 NULL，
AI 现场生成的题不带指纹，因此不会互相冲突）。

导入、AI 生成、重复打包三条路径共用同一指纹口径 → 同一道题不会重复入库。

### 2.5 填空辅助记忆清单 → 完整知识点（2026-09-29 修，用户反馈「不要题目，只展示知识点」）

**症状**：点开「填空速记」的知识点，正文是题目形态：
`信息系统生命周期的5 阶段是----（）、（）、（）、（）、（）；` —— 用户是来学习的，不是来做题。

**根因**：这类清单 PDF **自带两版**：前几页是无答案版，后面几页是带答案版。
旧解析把两版合并成「题目 + 【答案】 + 答案」，前端默认折叠答案，做成自测题。

**修法**：按页切两版 → 各自成条 → **按序配对 → 答案直接嵌入正文**（`tools/gx_parse.py::_parse_fill`），
最终 content 是完整陈述句，kind 从 `recite` 改为 `list`，与学习场景统一：

```
信息系统生命周期的5 阶段是系统规划、系统分析、系统设计、系统实施、系统运维；
```

四个关键设计：

1. **分版依据仍是「页」，不是「行」**。实测 32/32 份清单都满足「前若干页含空括号、
   其后页面一个空括号都没有」，`_fill_split_pages()` 按页判，边界不会切错。
2. **配对用「骨架序列」做 difflib 对齐**，不按下标硬配。两版断行不同会出现
   「空版拆成 2 条、答案版并成 1 条」（第 1 章「车联网的 3 层体系」就是），硬配会让其后所有条目错位。
3. **答案直接嵌入**：`_fill_to_full()` 去掉 `----` 占位符、去掉 `（答案）` 括号、
   清理 PDF 断词在汉字之间产生的空格。
4. **正文变了必须重算指纹**，否则合并结果与旧的分版行撞同一指纹，重新导入时不会更新。

**体量**：490 条全部转为完整知识点，kind=`list`；前端不再展示「填空速记」标签和「显示/收起答案」按钮。

**存量数据修复**（解析器改了，库里旧数据不会自己变）：

```bash
# 线上服务器部署目录
python tools/fix_gx_recite_merge.py            # 预演：只统计 + 抽样展示
python tools/fix_gx_recite_merge.py --apply    # 实际写入（幂等，重复跑无副作用）
```

脚本不依赖源 PDF，纯按库内数据重建；配对规则与解析器 **共用** `gx_parse._fill_groups`，
保证「就地修复」与「重新导入」结果一致。

> ⚠️ **修复后若要重新导入资料**：必须先在本地用**新解析器**重新生成数据包（`tools/gx_pack.py`）。
> 拿旧数据包重导会把空版行又插回来 —— 旧包的指纹对应已被删掉的分版行，
> 而库里现在存的是合并后的正文指纹。

### 2.6 知识点清单正文重解析 → 离线回填（2026-09-29 修，用户反馈「完全不可用」）

**症状**：点开知识点清单，正文是一整坨连写的句子：

```
网络存储3种技术----直接附加存储DAS ----无需网络、直连、很难扩展…；网络附加存储NAS----需要网络…
```

**根因**：这类 PDF 用 `----` 表达层级（「主题----术语----描述」），而 `read_pdf()` 用的
fitz `get_text("text")` **不保留缩进**——每行的行首缩进全是 0。层级信息在入库那一刻
就永久丢失了，从库里的 content 反推不出多级结构。

**解法**：`tools/gx_pdf_tree.py` 改用 `get_text("rawdict")` 拿**每个字符的 bbox**，用真实
缩进坐标还原层级树（单调栈建树）。实测同级兄弟左边界几乎重合（DAS 164.0 / NAS 162.9，
差 1.1pt），跨级差很远（3种数据结构模型 143.0 / 层次模型 264.4，差 121pt），可以精确判定。

#### 为什么必须「对齐后回填」，不能重新导入

卡片与页**不是**一一对应：实测 36 份清单没有一份是 1:1（130 页 vs 102 卡是常态，
也有 16 页只切出 2 卡的）。所以既不能「按页数重建卡片」（会改变卡片数量，已读记录会乱），
也不能「按页序硬配」（会整份错位）。

`tools/gx_rebuild_list.py` 的做法是**内容对齐**：

1. **相似度用字符多重集 Jaccard**。新旧正文的差异只有三处：删 `----`、加缩进空格、
   加项目符号 `•`。归一化（只留中日韩文字与字母数字）后两边字符多重集几乎相同，
   天然免疫「一行拆多行 / 多行并一行」。用多重集而非集合，防止长段落靠字表重合骗分。
2. **单调 DP 把页切成连续段分给卡片**，最大化总重合度 —— 不跳页、不乱序。
   段长上限按 `页数/卡数` 动态放宽（10 页 1 卡要能一次吃完；130 页 102 卡仍限 4 页，才跑得动）。
3. **末段强制用完所有页**。否则「整章只有 1 张卡」时，多重集会因重复字而惩罚吃多页，
   结果只吃 1 页、后面全丢（这个坑实测踩到过）。
4. **没有 `----` 的页不参与对齐**（封面 / 目录 / 版尾），避免把「www.luckeeinc.com」
   这类水印灌进正文。

安全边界：对齐分数 < 0.45、或新正文归一化长度不到旧正文一半的，一律**跳过不写补丁**——
宁可留旧内容，也不能把正文改没。

#### 指纹碰撞必须消解（否则 `--apply` 撞唯一索引 1062）

资料里「分课 PDF」与「汇总 PDF」内容重叠（如「第3章 信息系统治理」同时在第41课清单和
「技术管理（第1~5章）汇总」里），会造出两类重复，`resolve_fingerprints()` 分别处理：

| 类型 | 表现 | 后果 | 处理 |
|---|---|---|---|
| `old_fingerprint` 相同 | 库里是同一行，补丁里两条 | 第二条查不到 old 行 | 去重，只留一条 |
| `old` 不同、`new` 相同 | 库里两行，重解析后正文一致 | **写库撞 `ux_gx_knowledge_fingerprint`（1062）** | 把 `source_file` 纳入指纹；仍撞再纳入 `old_fingerprint` |

⚠️ **第二类干跑查不出来**：逐条检查时另一条还没写入、指纹仍是旧值，于是干跑报告
「冲突 0」，真正 `--apply` 才炸（2026-09-29 线上实测）。所以：

- 生成补丁时就消解（按行去重后再统计，不用遍历序号，保证补丁可重现）；
- `gx_apply_content_patch` 改成**一次性集合预检**（`_plan`）：先把所有相关指纹捞出来，
  在内存里连同「本批内部互相冲突」一起判，并按 id 最小者放行的规则保证确定性；
- 加载补丁时先 `selfcheck()`，旧版补丁（有重复新指纹）直接拦下并提示重新生成。

#### 两步走（本地解析 → 线上回填）

```bash
# ① 本地（资料 PDF 所在的机器）：只读 PDF、只写 JSON，不连数据库
.venv/Scripts/python.exe tools/gx_rebuild_list.py            # 全量 36 份，约 40 秒
.venv/Scripts/python.exe tools/gx_rebuild_list.py --only 第2章   # 抽查单份

# 补丁产出 data/gx_content_patch.json（约 770KB）。data/ 被 .gitignore 忽略，
# 需自行传到服务器（scp / rsync），不要走 git。

# ② 线上服务器部署目录：只读补丁、只写库
python tools/gx_apply_content_patch.py            # 默认干跑，先看命中率
python tools/gx_apply_content_patch.py --apply    # 确认没问题才落库
```

**更新方式是按 `old_fingerprint` 就地更新同一行**，不改主键。因此卡片数量与顺序完全不变，
`gx_knowledge_reads`（已读明细）按 knowledge_id 关联也不受影响。重复执行幂等：
已回填的行其指纹已是 new_fingerprint，会被判为「已回填」跳过。

**实测体量（2026-09-29）**：36 份清单 370 条卡片 → 卡片级条目 333 条，其中 123 条是同卡
重复（已去重），**最终补丁 210 条**，跳过 37 条（多是「重点ITTO」表格页，本身没有层级符，
重解析无意义）。对齐分数 ≥0.9 的占 94%；10 条发生新指纹碰撞，已加盐消解。

> ⚠️ **回填后若要重新导入资料**：仍会按旧解析器产出旧格式正文，需重跑本回填链路。
> 补丁里同时保留了 `old_fingerprint` 与 `new_fingerprint`，重跑是幂等的。
> 注意加过盐的条目（`fp_salted: true`）指纹含 `source_file`，与 `gx_parse` 的导入指纹
> 不一致 —— 所以重新导入后务必重跑本链路，不能指望靠指纹去重拦住重复行。

### 2.7 计算题参数化生成（2026-09-30，用户反馈「题目太少」）

**症状**：线上计算专题只有 53 道、案例题 17 道，刷几轮就见底。

**为什么不再去解析 PDF**：本地 452 份资料里题目类 PDF 基本已经榨干（`files_parsed
433/602`，跳过的 156 个里 95 个是音频、50 个是项目模板）。剩下没解析的「回家作业」
是**作图题**（画单代号图、双代号箭线图），PDF 文本抽出来只有 `A 1 2 3 4 5` 这类图的
标注碎片，做不成题目。

**解法**：软考高项的计算考点是**收敛的**——历年真题只是换数字。所以写
`tools/gx_calc_gen.py` 按公式参数化生成，不调 AI、零成本、答案由公式算出必然正确。

| 考点 | 公式 | domain |
|---|---|---|
| 三点估算 | 三角 `(O+M+P)/3`、β `(O+4M+P)/6`、σ `(P−O)/6`，以及反推最悲观值 | 成本管理 |
| 挣值分析 | CV/SV/CPI/SPI/EAC(典型·非典型)/ETC/VAC/TCPI | 成本管理 |
| 沟通渠道 | `n(n−1)/2`、新增 m 人后增量 | 沟通管理 |
| 关键路径 | 6 活动网络求总工期 / 某活动总浮动 | 进度管理 |
| 决策树 EMV | 两方案期望货币价值择优 | 风险管理 |
| NPV / 回收期 | 折现净现值、静态投资回收期 | 项目立项管理 |
| ROI / 盈亏平衡 | 投资收益率、盈亏平衡点产量 | 项目立项管理 |
| 后悔值决策 | 最小最大后悔值 | 风险管理 |
| 指派问题 | 4×4 匈牙利法（枚举 24 种分配） | 资源管理 |

**四条硬约束**（都踩过或差一点踩到）：

1. **可重现**：固定随机种子，同一参数两次跑出完全一致的题目。否则每次重跑指纹都变，
   线上导入没法幂等。
2. ⚠️ **先打乱数值、再生成字母前缀**。反过来（先写好 `"A. 104"` 再 shuffle）会让
   字母与位置脱钩 —— 实测 180 道题答案全部指向错误选项，而「答案字母合法」「四个
   选项互不相同」两项检查**全都过得去**。所以 `verify()` 拿 `answer_text`（公式算出的
   正确值）与「答案字母实际指向的选项文本」比对，这条断言在测试里钉死了。
3. **数值干净**：参数按整除条件挑选（如三点估算要求 `d2−d1 ≡ 0 (mod 6)`，让三角与
   β 的估算值都是整数），选项里不允许出现 `1250.3333333`。
4. **不与真题撞车**：生成时传入 `pack_choice.json` 已有的 fingerprint 集合，撞车的丢弃。

**产出与导入**：

```bash
.venv/Scripts/python.exe tools/gx_calc_gen.py --verify           # 生成 + 答案自检
.venv/Scripts/python.exe tools/gx_calc_gen.py --per-kind 60      # 每个考点多生成些
# → data/gx_materials/pack_calc_gen.json（格式同 pack_choice.json）
```

单独成文件（而不是并入 `pack_choice.json`）是为了**不被 `gx_pack.py` 重跑冲掉**。
`import_gx_materials.py` 已把该文件并入选择题一起导入（按 fingerprint 幂等）。

**实测**：默认每考点 40 条 → **360 道计算题**；答案分布 A/B/C/D 均衡（防止闭眼选一个
字母），9 个考点全覆盖。

### 2.8 案例题「按小问刷」（2026-09-30，用户反馈「案例题太少」）

资料里只有 **17 道案例大题 / 61 个小问**，按整卷刷一次要写完全部小问才能批改，
既慢又费 AI（prompt 与作答都很长）。选定方案是**在展示层把小问展开成一问一练**，
**不新增 `gx_questions` 行**（改数据要把 61 条新行的指纹、导入、去重全重来一遍，
收益却只是「列表长一点」）。

```
GET  /case/sub/list   17 道大题 → 61 条小问（key = "{question_id}#{sub_index}"）
POST /case/sub/grade  只把「这一小问 + 背景」交给 AI 批改
```

**三条约定**：

1. **`key` 只是展示键**：小问没有独立题目行，`key` 供前端索引草稿与历史得分。
   历史得分存 `localStorage`（`gx_case_sub_scores_<user>`）—— 后端没有「小问」这一层，
   不值得为它加一张表。
2. **错题本仍按整道大题归集**：小问批改低于 60 分 → `GxWrong` 记的是大题 id，
   点开仍是完整案例（跳转逻辑与整卷模式一致），不会因为刷了 4 个小问就变成 4 条错题。
3. **背景必须带、其他小问不带**：小问依赖情境，prompt 里必须有完整背景；但只把
   **当前小问**的题干与参考答案要点给 AI —— 否则就是整卷批改，失去按问刷的意义
   （测试里钉死了「其他小问题干不得出现在 prompt 中」）。

路由上 `/case/sub/list` 与先注册的 `/case/{qid}` 不冲突：`qid` 是 int 转换器，
`"sub"` 转 int 失败会继续匹配后续路由（测试 `test_sub_route_not_shadowed_by_case_detail` 钉死）。

批改返回额外带 `points`（小问分值）与 `earned`（百分制 × 分值，如 85 分 × 12 分 = 10.2），
前端展示「折合 10.2 / 12 分」。

## 三、错题闭环（本模块的核心需求）

需求原话：「每个题目做完之后需要自动分析错题，并将错题进行入库，后续进行练习」。
拆成四段实现：

```
作答 → 判分（服务端） → 违反/低于及格线 → 入错题本 → 自动 AI 错因分析 → 错题重练
```

### 3.1 入库规则

| 情形 | 是否入错题本 | 说明 |
|---|---|---|
| 选择题答错 | ✅ `kind=choice` | `wrong_count+1`，连对计数清零 |
| 选择题**资料无参考答案** | ❌ | `judged=false`：不判错、不入库、不计分（打印版资料约 5% 无答案，误判会污染错题本） |
| 案例 / 论文批改 < 60 分 | ✅ `kind=case/essay` | 阈值 `SUBJECTIVE_PASS_SCORE = 60` |
| 重做连对 3 次 | ⬆️ 自动掌握 | `MASTER_STREAK = 3`，掌握后不再出现在重练池 |

### 3.2 错因分析为什么是「懒生成」

判分接口必须快（一次提交最多 20 题），而 AI 分析每题要数秒——同步做必然超时。
因此设计为：**提交后由前端立刻调 `POST /api/gx/wrong/analyze`**，
用户感知上仍是「做完立刻有分析」（一次提交最多自动分析 3 道，余下在错题本逐题点），
分析结果落 `gx_wrongs.wrong_reason` 缓存，再看错题本不再重复扣费。

### 3.3 错题重练

`quiz_pick(scope="wrong")` 从错题本取未掌握的题，**不再过滤「做过的题」**
（否则错题永远刷不到），按 `wrong_count` 降序 —— 错得多的先练。
案例/论文错题点「打开原题重做」跳到对应页签，批改达标后自动累计连对。

## 四、数据库表（8 张，迁移 081 + 082 + 084）

| 表 | 作用 | 关键列 |
|---|---|---|
| `gx_knowledge` | 知识点 | `domain/chapter/kind/source_file/seq/fingerprint(唯一)` |
| `gx_questions` | 题目（三类共用） | `qtype`、`options_json`、`answer`、`sub_questions`、`chapter`、`source_kind`、`deck`、`fingerprint(唯一)` |
| `gx_attempts` | 作答记录 | 一题一行，供进度聚合与「未做过」排除（见下） |
| `gx_wrongs` | 错题本 | `kind/best_score/last_score/wrong_reason/reason_at/correct_streak/is_mastered` |
| `gx_case_grades` | 主观题批改留痕 | `kind`、`score`、`feedback`、`rubric_json` |
| `gx_progress` | 分知识域进度 | `user_id + domain` 一行 |
| `gx_knowledge_reads` | 知识点已读明细（084） | `user_id + knowledge_id` 唯一 —— 「已读」的**真相源** |
| `gx_materials` | 资料归档审计 | `rel_path(唯一)/category/sub_kind/items/skipped/error/reason` |

**已读为什么要单独一张表（084）**：`gx_progress.knowledge_read` 是个 `Integer` 计数，
只能回答「读过几条」，**回答不了「哪几条读过」**，而列表要给每条打「已读」标记。
所以 `gx_knowledge_reads` 是真相源，`knowledge_read` 降级为它的**去重计数缓存**
（进度页显示用，沿用本项目「行为时增量累加、读时零聚合」的口径）。
计数**只在首次阅读时 +1** → 「读过知识点」= 去重条数，反复打开同一条不会把数字刷大；
明细与计数由唯一写入口 `services/gaoxiang.mark_knowledge_read()` 一起动，不留第二处写入。

**`sub_questions` 字段三种形态**：
- 选择题：`NULL`（选项在 `options_json`）
- 案例题：`[{q, answer, points}]` —— `answer` 是参考答案要点，批改时作评分依据
- 论文题：`[{q, answer:"", points:0}]` —— `q` 是论述要求

### 5.1 前端交互约定（都是踩过坑后定下来的）

- **先配置再出题**：进页**不自动出题**，用户选好知识域/资料/章节/题型后点「开始出题」。
- **AI 出题必须显式勾选**（`gxUseAi`，默认关）：关闭时请求带 `source=import`，只从已导入
  真题里取，**零 AI 费用**；打开才带 `source=all`（题库不足由 AI 补题并落库）。错题重练
  固定 `import`。题库为空且未勾选时提示「勾选『允许 AI 出题』可让 AI 补题」，而不是偷偷扣钻。
- **知识点页按资料类型分节**：不选类型时按 `catalog.knowledge_kinds` 顺序分组渲染
  （每节带类型名、条数与「已读 x」），选了类型则只显示该类型；卡片显示「类型角标 + 知识域 · 章节 + 摘要」，
  正文详情走**结构化渲染**（`logic/gaoxiang.js::gxKParseBlocks`/`gxKBlocksHtml` 解析成小标题/条目/
  段落块），不再是挤成一坨的纯文本。⚠️ 那些块由 `v-html` 产出，**不带 scoped 的 `data-v`
  属性**，所以样式必须用 `:deep()` 穿透 —— 否则编译/构建全绿而样式一条不生效
  （说明见 `views/GaoxiangView.vue` 样式块内 `.gx-kcontent` 段顶部的 `:deep()` 注释，约 635 行）。
- **已读标记（084）**：点开详情即记为已读 —— 弹层里显示「✓ 已读」，关掉后列表那条也立刻出现
  「已读」角标，**不重拉列表**（`gxMarkRead()` 就地替换该条，用户的分节与滚动位置都不跳）。
  已读按用户隔离；列表的 `read` 由后端按 user 批量查 `gx_knowledge_reads` 得出。
- **入口不对普通用户展示**：`nav.js` 里没有这一项（移动端 TabBar 6 项也早已占满）。
  私有入口两条：设置页「⚙️ 其他 → 关于」**连点 5 次**（`gxSecretTap()`，第 3 次起提示还需几次）
  或 URL 直达 `https://<域名>/#/gaoxiang`（hash 路由已把 `/:tab` 映射为 App.vue 的 tab）。

## 六、硬性约束与踩过的坑

1. **AI 调用不得持 DB 连接**（全站铁律）：`chat_with` 前必须 `db.close()` 或改用独立短会话。
   `/quiz/generate` 连 `Depends(get_db)` 都不用 —— AI 补题写库后要回读新行，
   而请求级会话在 REPEATABLE READ 下快照冻结，读不到新建的行。全程独立短会话。
2. **已做题在 SQL 层排除**（`NOT EXISTS` 子查询）。早期实现是「取 `n*8` 行再在 Python 里剔除」，
   用户做满前 40 道后窗口内全是旧题 → 明明库里有上千道真题却判定「资料不够」回退 AI 出题（白扣费）。
   防回归用例：`tests/test_gaoxiang.py::test_quiz_pick_excludes_done_at_sql_level`。
3. **无参考答案的题不得判错**：打印版资料约 5% 没有答案，判错会把正确答案的题塞进错题本。
   接口返回 `judged=false`，前端提示「本题资料未提供参考答案，不计分」。
4. **数据库写入只能在线上本机**：本地 `.env` 指向线上库克隆，导入/补数据一律走线上服务器。
5. **MySQL 不给 MEDIUMTEXT 加 DEFAULT**；`fingerprint` 补列必须可空（唯一索引只允许一个 NULL）。
6. **填空辅助记忆清单已统一转成完整知识点**：原「题目 + 【答案】 + 答案」的自测形态
   改为答案直接嵌入正文，kind 从 `recite` 变为 `list`。存量数据用 `tools/fix_gx_recite_merge.py`
   就地修复。防回归用例 `tests/test_gx_materials.py::test_fill_to_full_expands_blanks_into_plain_text`。
