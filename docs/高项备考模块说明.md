# 高项备考模块说明（软考高级 · 信息系统项目管理师）

> 面向**非学生成人用户**的备考模块，入口 `tab='gaoxiang'`（导航「高项备考」）。
> 与小学侧完全独立：不挂 `check_quiet_hours`（成人晚间备考是核心场景），
> 科目/年级/教材版本维度均不共享。
>
> 最后更新：2026-09-28

---

## 一、它解决什么问题

备考资料散落在 `temp/软考【高项】2026年5月班备考资料` 里的 602 个文件（PDF / Word / 图片），
人工翻找无法形成练习闭环。本模块把资料**按四类落进数据库**，并在做题后**自动分析错题、入库、供后续重练**：

| 类别 | 落表 | 前端入口 | 判分方式 |
|---|---|---|---|
| 知识点 | `gx_knowledge` | 知识点页签 | 不计分（阅读） |
| 选择题练习 | `gx_questions`（`qtype=single/multi`） | 刷题页签 | 服务端判分（字母归一比对） |
| 案例分析练习 | `gx_questions`（`qtype=case`） | 案例页签 | AI 按要点批改 |
| 论文练习 | `gx_questions`（`qtype=essay`） | 论文页签 | AI 四维评分 |
| 其他（未命中规则的资料） | `gx_materials` 归档 | — | 仅审计，可回溯为什么不入库 |

## 二、资料 → 题库的数据流（本地打包 → 线上写库）

```
temp/软考【高项】…/*.pdf
        │  ① tools/gx_parse.py   解析引擎（分类 / 章节归一 / 五种解析器 / 指纹去重）
        ▼
   data/gx_materials/pack_*.json + manifest.json      （本地产出，不连数据库）
        │  ② scp 上传（只传数据包）
        ▼
   线上服务器 ③ tools/import_gx_materials.py load      （幂等写 MySQL）
```

两段式的原因：解析依赖 PyMuPDF（必要时 LibreOffice 处理 OLE 二进制 .doc），本地方便；
而写库必须落在**线上真库**——本地 `.env` 指向的是线上库克隆（`192.168.2.158`），
铁律：绝不对克隆库跑写库脚本。

命令与体量见 [DEPLOY.md §5.5](../DEPLOY.md#55-高项备考资料导入可选一次性)。

### 2.1 分类规则（`tools/gx_parse.py: classify()`）

按**顶层目录**判类别，再看子目录/文件名判子类；命中不了进 `其他` 并记 `reason`。
顶层目录名本身有陷阱（如「知识点」目录里混着每日一练截图），因此子类判定优先于目录名。

### 2.2 章节归一（`app/domains/assessment/services/gaoxiang.py: normalize_chapter()`）

三级回退，缺一级就大面积空域：

1. 章号表达式：`第12章`、`第6、7章`、`第8~10章` → 第 8/9/10 章；
2. 小节号：`第6.4.1节` → 第 6 章（每日一练文件名大量使用，不认它约 7% 题目域名空）；
3. 域名反查：`风险管理` → 第 15 章（别名表 `DOMAIN_ALIASES`，长键优先）。

考纲已从早期「十大知识域」扩展为**第 1~24 章**（信息化发展 / 信息技术发展 / 绩效域 /
法律法规与标准规范…）——真实资料覆盖全书，只认十大域会让大半题目无处归置。
第 8~17 章名称保持与旧版一致，便于既有数据对齐。

### 2.3 去重与幂等（同一套指纹）

`fingerprint()` = `sha1(归一化文本)[:16]`，落在 `gx_questions.fingerprint` /
`gx_knowledge.fingerprint` 的**唯一索引**上（列可空：MySQL 唯一索引允许一个 NULL，
AI 现场生成的题不带指纹，因此不会互相冲突）。

导入、AI 生成、重复打包三条路径共用同一指纹口径 → 同一道题不会重复入库。

### 2.4 实测体量（2026-09-28 全量跑）

| 类别 | 原始 | 去重后 | 字段覆盖率 |
|---|---:|---:|---|
| 知识点 | 5775 | **2851** | 知识域 95.2% / 章节 93.8% |
| 选择题练习 | 3173 | **1670** | 知识域 93.1% |
| 案例分析练习 | 18 | **17** | 100% |
| 论文练习 | 12 | **6** | 100% |
| 合计 | 8978 | **4544** | — |

602 个文件 → 442 个解析单元（跳过 156：重复/无答案变体/非题库文件）。
「解析出 0 条目」4 个（印刷版思维导图、两个纯图形回家作业、英语词汇扫描件），
5 个扫描件（第四版教材、考纲、考生操作手册）无文本层报错 —— 均属合理。

## 三、错题闭环（本模块的核心需求）

需求原话：「每个题目做完之后需要自动分析错题，并将错题进行入库，后续进行练习」。
拆成四段实现：

```
作答 → 判分（服务端） → 违反/低于及格线 → 入错题本 → 自动 AI 错因分析 → 错题重练
```

### 3.1 入库规则

| 情形 | 是否入错题本 | 说明 |
|---|---|---|
| 选择题答错 | ✅ `kind=choice` | `wrong_count+1`，连对计数清零 |
| 选择题**资料无参考答案** | ❌ | `judged=false`：不判错、不入库、不计分（打印版资料约 5% 无答案，误判会污染错题本） |
| 案例 / 论文批改 < 60 分 | ✅ `kind=case/essay` | 阈值 `SUBJECTIVE_PASS_SCORE = 60` |
| 重做连对 3 次 | ⬆️ 自动掌握 | `MASTER_STREAK = 3`，掌握后不再出现在重练池 |

### 3.2 错因分析为什么是「懒生成」

判分接口必须快（一次提交最多 20 题），而 AI 分析每题要数秒——同步做必然超时。
因此设计为：**提交后由前端立刻调 `POST /api/gx/wrong/analyze`**，
用户感知上仍是「做完立刻有分析」（一次提交最多自动分析 3 道，余下在错题本逐题点），
分析结果落 `gx_wrongs.wrong_reason` 缓存，再看错题本不再重复扣费。

### 3.3 错题重练

`quiz_pick(scope="wrong")` 从错题本取未掌握的题，**不再过滤「做过的题」**
（否则错题永远刷不到），按 `wrong_count` 降序 —— 错得多的先练。
案例/论文错题点「打开原题重做」跳到对应页签，批改达标后自动累计连对。

## 四、数据库表（7 张，迁移 081 + 082）

| 表 | 作用 | 关键列 |
|---|---|---|
| `gx_knowledge` | 知识点 | `domain/chapter/kind/source_file/seq/fingerprint(唯一)` |
| `gx_questions` | 题目（三类共用） | `qtype`、`options_json`、`answer`、`sub_questions`、`chapter`、`source_kind`、`deck`、`fingerprint(唯一)` |
| `gx_attempts` | 作答记录 | 一题一行，供进度聚合与「未做过」排除（见下） |
| `gx_wrongs` | 错题本 | `kind/best_score/last_score/wrong_reason/reason_at/correct_streak/is_mastered` |
| `gx_case_grades` | 主观题批改留痕 | `kind`、`score`、`feedback`、`rubric_json` |
| `gx_progress` | 分知识域进度 | `user_id + domain` 一行 |
| `gx_materials` | 资料归档审计 | `rel_path(唯一)/category/sub_kind/items/skipped/error/reason` |

**`sub_questions` 字段三种形态**：
- 选择题：`NULL`（选项在 `options_json`）
- 案例题：`[{q, answer, points}]` —— `answer` 是参考答案要点，批改时作评分依据
- 论文题：`[{q, answer:"", points:0}]` —— `q` 是论述要求

## 六、硬性约束与踩过的坑

1. **AI 调用不得持 DB 连接**（全站铁律）：`chat_with` 前必须 `db.close()` 或改用独立短会话。
   `/quiz/generate` 连 `Depends(get_db)` 都不用 —— AI 补题写库后要回读新行，
   而请求级会话在 REPEATABLE READ 下快照冻结，读不到新建的行。全程独立短会话。
2. **已做题在 SQL 层排除**（`NOT EXISTS` 子查询）。早期实现是「取 `n*8` 行再在 Python 里剔除」，
   用户做满前 40 道后窗口内全是旧题 → 明明库里有上千道真题却判定「资料不够」回退 AI 出题（白扣费）。
   防回归用例：`tests/test_gaoxiang.py::test_quiz_pick_excludes_done_at_sql_level`。
3. **无参考答案的题不得判错**：打印版资料约 5% 没有答案，判错会把正确答案的题塞进错题本。
   接口返回 `judged=false`，前端提示「本题资料未提供参考答案，不计分」。
4. **数据库写入只能在线上本机**：本地 `.env` 指向线上库克隆，导入/补数据一律走线上服务器。
5. **MySQL 不给 MEDIUMTEXT 加 DEFAULT**；`fingerprint` 补列必须可空（唯一索引只允许一个 NULL）。
